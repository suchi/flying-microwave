以下は、メンテナーに渡す手順と同じ内容である。

対象: GitHub Releaseの下書き`v0.3.0-alpha.4`の`FlyingMicrowave-0.3.0-alpha.4-windows-x64.zip`。3Dの電子レンジの見た目と動き、LEDの時計、一緒に飛ぶ食べ物を実機で見て、キーの遅れの直し方が実機でも働くかを確かめるための確認です(`v0.3.0-alpha.3`で頼む予定だった確認を、この版にまとめました)。結果は、番号ごとに「OK」「NG(見えたこと)」「できなかった」で返してください。値を決める項目(A-2など)は、「このままでよい」か「もっと遅く」のような一言で構いません。最後に、ログと記録のファイル(手順Z)も送ってください。

## 準備

- P-1. GitHubのリリースの画面で、下書きの`v0.3.0-alpha.4`を開く。公開は、まだしない(確認のあとのZ-4で判断する)。
- P-2. 下書きからzipをダウンロードし、ハッシュを確かめる。coreutilsの入ったcmdで、ダウンロードしたフォルダで次を実行する。

  ```bash
  sha256sum FlyingMicrowave-0.3.0-alpha.4-windows-x64.zip
  ```

  表示の先頭の64桁が`7be36fc5a14c9a0ef2595407af3672a425581c6db99f62530a537a24b759bcdb`であること(値は、リリースのワークフローのReleaseの17回目の、下書きを作るジョブのログの`sha256sum`の出力の行。リリースの`SHA256SUMS.txt`にも同じ値がある)。一致しないときは、先に進まずに知らせてください。
- P-3. エクスプローラーの「すべて展開」で、前の版とは別の新しいフォルダに展開し、`FlyingMicrowave.scr`を右クリックして「インストール」を選ぶ(Windows 11では「その他のオプションを確認」の中)。スクリーンセーバーの設定の画面で「FlyingMicrowave」が選ばれていること。
- P-4. 設定画面(設定の画面の[設定])で「Defaults」を押してから「OK」を押す(既定の設定に戻す)。
- P-5. 前のログを消す(cmdで実行する)。

  ```bash
  del %TEMP%\flying-microwave.log
  ```

## A. 3Dの見た目と動き(E-1、G-3、D-12)

設定の画面の「プレビュー」ボタンで全画面にし、1〜2分見てください。

- A-1. 成功の見え方: ほぼ黒(わずかに青みのある夜空)の背景の上を、立体的な電子レンジが、それぞれ違う向きで回転しながら、右上から左下へ飛ぶ。奥のものほど小さく、ゆっくり見える。ドアがヒンジの回りに開いたり閉じたりし、庫内のターンテーブルが回る。背景が白や灰色ではないこと。
- A-2. 値の判断(一言で): 回転の速さ、既定の大きさ、飛ぶ速さ、遠近のきつさ(手前と奥の大きさの差。視野角)、手前と奥の分かれ方。
- A-3. 回転による明るさの変化(G-3): 面の明るさが変わるとき、点滅のようにちらついて見えないこと。
- A-4. 縁: 電子レンジの縁のギザギザが、気になるかどうか(気になるなら、なめらかにする処理を加えることを検討する)。遠くで斜めを向いたドアの縁が、欠けて見えないこと。
- A-5. 画面の端: 電子レンジが、見えたまま急に消えたり、画面の中の何もない所に急に現れたりしないこと(画面の外に出てから入れ直す)。入れ直して現れる電子レンジは、色や向きがそのたびに違う。
- A-6. 設定画面で Speed を 2.0 にして OK を押し、全画面にする。飛ぶ速さだけが上がり、回転の速さとドアの開け閉めの速さは変わらない。確かめたら、Speed を 1.0 に戻して OK を押す。

## B. 飛び方の選択(手動テストの項目30)

- B-1. 設定画面の Flight のタブに、Flight style の行(Tumbling と Level)があり、ほかの行やボタンと重ならない。
- B-2. Level を選んで OK を押し、全画面にする。すべての電子レンジが同じ向き(正面、右の側面、上面が見える向き)で飛ぶ。設定の画面のプレビュー枠も同じになる。
- B-3. Tumbling に戻して OK を押し、全画面にする。それぞれ違う向きで回転しながら飛ぶ。

## C. LEDの時計(手動テストの項目31)

- C-1. 全画面で、電子レンジの正面のLEDに、PCの時計と同じ時刻(時と分)が出て、コロンが1秒ごとに点滅する。分が変わると、表示も変わる。
- C-2. 設定画面の Display のタブで、Show clock on display と Clock format の行が、スクロールで見られる。
- C-3. Clock format を 12-hour にして OK を押し、全画面にする。十の位の0が出ない(例「 9:05」)。午後に確かめた場合は、左下の点が光る(午前か午後のどちらで確かめたかを書いてください)。
- C-4. Show clock on display をオフにして OK を押し、全画面にする。LEDの画がすべて消えた表示(薄い「88:88」)になる。確かめたら、オンと 24-hour に戻して OK を押す。

## D. 左の側面、上面、底面の絵(手動テストの項目32)

回転して飛ぶ(Tumbling の)電子レンジで見てください。Level では、左の側面と底面は見えない向きです。

- D-1. 左の側面に通気口(正面に近い側)、上面に縁の継ぎ目、底面に4つの脚と銘板が見える。それぞれの面が、正面や右の側面とつながった向きになっている(通気口が背面の側にない、脚が正面の側にずれていない)。
- D-2. Size を 2.0 にして OK を押し、全画面にする。電子レンジが大きくなり、手前の大きな電子レンジで、この3面が、正面や右の側面と比べて気になるほどぼやけていないかを見る。確かめたら、Size を 1.0 に戻して OK を押す。

## E. 飛ぶ食べ物(手動テストの項目33)

- E-1. 設定画面の Flight のタブに、Number of food items の行(0〜30のスライダー、既定4)がある。既定の4のまま全画面にすると、電子レンジと一緒に食べ物が飛ぶ(種類は出るたびに乱数で決まるため、4個では4種類がそろわないことが多い)。
- E-2. Number of food items を30にして OK を押し、全画面にする。弁当(黒いトレーと、ふた越しのご飯とおかず)、ポップコーンの袋(赤と白の縞)、マグカップ(青緑で、取っ手と飲み物)、肉まん(白い半球で、頂にひだ)の4種類が見える。どれも電子レンジより小さく、電子レンジと同じく右上から左下へ飛び、奥のものほど小さく遅く見える。
- E-3. 食べ物の大きさの判断(一言で。D-17の(3)の出発点の値): 小さすぎる、大きすぎる、このままでよい。
- E-4. 30のまま Flight style を Level にして OK を押し、全画面にする。食べ物も回転しなくなる。マグカップの取っ手はどれも右に見え、ポップコーンの袋はどれもポップコーンの窓がある面が正面に見え、弁当はどれもふた越しの中身が上に見える。確かめたら、Tumbling に戻して OK を押す。
- E-5. Number of food items を0にして OK を押し、全画面にする。食べ物は飛ばない。

## F. 終了の速さ(N-02)と動きの滑らかさ(D-20)

- F-1. 全画面で、キーを押す。画面が、もたつかずに一瞬で消えること(数値は実機では測れないため、目で見た判定と、CIの値を合わせて記録する)。何回か試し、一度でも0.5秒ほど残ったら、そのことを書く。
- F-2. 動きの滑らかさ: 全画面で1分ほど見て、電子レンジと食べ物が、ときどき一瞬止まったり、引っかかったりして見えないこと。止まって見えたら、どれくらいの頻度か(1秒に何回、数秒に1回など)を書く。

## G. 負荷とメモリ(N-03、N-04)

全画面はキーやマウスの操作で終わるため、タスクマネージャーに切り替えて値を読むことはできません。cmdから全画面を起動し、1分後と5分後に、使ったCPU時間とメモリを記録します。

- G-1. 設定画面で「Defaults」を押してから「OK」を押す(既定の設定に戻す)。
- G-2. cmdで、展開したフォルダに移動してから、次の1行を実行する。全画面になったら、終わるまで(約5分。cmdに戻るまで)キーボードとマウスに触らないでください。

  ```bash
  start "" FlyingMicrowave.scr /s & timeout /t 60 /nobreak >nul & tasklist /v /fo list /fi "imagename eq FlyingMicrowave.scr" > %TEMP%\fm-usage.txt & timeout /t 240 /nobreak >nul & tasklist /v /fo list /fi "imagename eq FlyingMicrowave.scr" >> %TEMP%\fm-usage.txt
  ```

- G-3. 約5分たってcmdのプロンプトが戻ったら、キーを押して全画面を終える。`%TEMP%\fm-usage.txt`に、2回分の「CPU時間」と「メモリ使用量」があること。あわせて、モニターの数・解像度・リフレッシュレートと、GPUの名前を書いてください。CPUの割合(論理1コアあたり)は、2回の「CPU時間」の差を240秒で割って、エージェントが求めます。目安は、論理1コアの10%以下(N-03。4Kモニター1台、60fps)、メモリが200MB以下で増え続けない(N-04)。
- G-4. 記録が空のときや、「情報: 指定された条件に一致するタスクは実行されていません」のようなメッセージのときは、そのまま書いてください。

## Z. 終わったあとと、送るもの

- Z-1. 設定画面で「Defaults」を押してから「OK」を押す(既定の設定に戻す)。
- Z-2. 次の2つのファイルを送ってください: `%TEMP%\flying-microwave.log`、`%TEMP%\fm-usage.txt`。
- Z-3. エージェントは、ログで次を判定する。
  - 起動の速さ(N-01): 起動の行(`Flying Microwave 0.3.0-alpha.4 started`。`crates/app/src/main.rs`の`run`)から、全モニターのウィンドウの行(`window N: inner ...`。ウィンドウを作って黒で塗ったあとに書く。`crates/app/src/saver.rs`の`create_black_window`)までが0.5秒以内、ウィンドウごとの`first frame presented`の行(`saver.rs`の`try_draw`)までが1秒以内。
  - 描くための合図(D-20、ADR-0028の「結果」の判定の基準): 全画面の終了ごとに、ウィンドウごとの要約の行(`window N: ... draws attempted, ... frames, ...`。`crates/app/src/diag.rs`の`FrameStats::summary`)の、`NotReady`のスキップの数と`drawn without signal`の数。合図が毎フレーム来ていれば、`drawn without signal`は0かごく少なく、`NotReady`はフレームの数よりずっと少ない。
  - 設定の反映: 全画面の起動ごとの`settings: Config { ... }`の行(`saver.rs`の`settings: {config:?}`)で、`style: Level`、`clock: Clock { enabled: false, format: H12 }`、`food_count: 30`などが、手順のとおりに変わっていること。
- Z-4. 確認の結果を見て、下書きを公開するかを判断する。公開するときは、「Set as a pre-release」のまま「Publish release」を押す(計画0001の7.3の手順4)。公開したら、知らせてください。

## 結果

2026-11-21に受け取った。メンテナーの報告は、A〜Gに問題はなく、電子レンジと食べ物の大きさと表示は、このままでよい(A-2、E-3)。

ログ(`flying-microwave.log`)と記録(`fm-usage.txt`)での判定:

| 項目 | 結果 | 根拠 |
| --- | --- | --- |
| 環境 | NVIDIA GeForce RTX 5060 Ti(DiscreteGpu、Dx12)。モニター2台(1600x1200と1280x1024)。リモートデスクトップでの実行 | `adapter:`と`monitor 0/1:`の行。記録のセッション名が`RDP-Tcp#1`。どちらのモニターもリフレッシュが32000mHzと記録され、描画は1秒に約32フレームだった |
| 起動の速さ(N-01) | OK | ウィンドウを作るまで26〜49ms(14回の全画面の28行の`window N: inner`。基準0.5秒)。最初のフレームまで423〜572ms(28行の`first frame presented`。基準1秒) |
| 描くための合図(D-20、ADR-0028) | OK | 全画面の14回の要約の行(`crates/app/src/diag.rs`の`FrameStats::summary`)が、すべて`0 drawn without signal`。`NotReady`は、約5分の実行(G-2)で各ウィンドウ1回だけで、ほかは0 |
| 終了の速さ | 速い | 全画面の14回で、`exit:`の行から`screensaver ended`の行まで34〜53ms。プレビューの28回で、`preview exit`の行から`preview ended`の行まで57〜121ms。CIのWARPの1.2〜2.0秒(incident 0033)とは大きく違う |
| 設定の反映 | 一部は確かめられなかった | 設定の行(`saver.rs`の`settings: {config:?}`)に、Speed 2.0、Level、Size 2.0、食べ物30、時計オフは出ている。C-3の12-hour(`format: H12`)と、E-5の食べ物の数0(`food_count: 0`)は、1回も出ていない。手順を行ったかは、ログからは分からない |
| メモリ(N-04) | OK | 全画面のプロセスは約188.6MBから188.8MB(4分の差。基準200MB以下で、増え続けない)。設定の画面のプレビュー枠のプロセスは約158MB |
| CPU(N-03) | 判定できなかった | 記録の「CPU 時間」が、2つのプロセスとも3回すべて`0:00:00`だった(手順では2回分のはずが3回分あった)。差から割合を求められない。理由は分からない |

確かめられなかったこと: C-3とE-5の設定の反映、CPUの割合、60Hzの画面での負荷と動きの滑らかさ(リモートデスクトップのため32Hzだった)、PCに直接つないだモニターでの見た目(A-3の回転による明るさの変化、A-4の縁。リモートデスクトップで見た画面だったため)。CPUの測り直しは、計画0005の作業10の6に登録した。
