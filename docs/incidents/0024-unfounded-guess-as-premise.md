# 0024: 記録にない過去の事実を、根拠のない推測で補い、異常の記録の前提にしようとした

- 日付: 2026-11-10
- ステータス: 対策中(規則と手順の対策は、2026-11-10にメンテナーが承認し、まだマージしていない)
- 関連: [0023](0023-tag-check-command-failed-in-cmd.md)(この異常が起きた記録)、[README](README.md)の手順2・3、AGENTS.mdの「情報源」

## 起きたこと

2026-11-10に、incident 0023(タグの前に件名を確かめるコマンドが、cmdで動かなかった)を記録する途中で、エージェントは、記録にない過去の事実(メンテナーがこれまでどのシェルでタグを付けていたか)を、根拠なしに「cmdで実行したのは今回が初めて」と推測し、それを記録の前提にしようとした。0023の最初の版(コミットする前のもの)にも、確かめていない記述(PowerShellなら動くこと、0016の手順を作ったときにシェルを確かめなかったこと)を、なぜなぜ分析の答えなどに書いていた。

メンテナーが指摘し、事実は、メンテナーはこれまでのタグ付けもエージェントの依頼に従ってcmdで行っていて、bashを前提にしたコマンドを依頼されたのは今回が初めて、だと分かった。エージェントは、0023を、メンテナーの指摘と履歴で確かめた事実だけで書き直した。

確かめた事実:

- エージェントは、過去のセッションでメンテナーに渡したコマンドを、記録にも記憶にも持っていない。「初めて」の推測の根拠は、「前回のシェルの記録がない」ことだけだった。記録がないことは、なかったことの根拠にならない。
- AGENTS.mdの「情報源」は、「一次情報で確認できない場合は、その旨を明記し、確認済みの事実と推測を区別する」としている。推測を推測と書けば書いてよい形で、推測に根拠を求めることと、推測を分析や判断の前提にしないことは、書かれていない。
- [README](README.md)の手順3は、なぜなぜ分析の「各段の答えは、確かめた事実で書く」としている。0023の最初の版は、確かめていない答えを書いていて、この手順を守っていなかった。
- メンテナーの環境や、メンテナーが行った過去の操作のように、メンテナーが知っている事実を、推測せずに尋ねる決まりはない。

## なぜなぜ分析

| なぜ | 答え(確かめた事実) |
| --- | --- |
| なぜ事実と違う前提を書いたか | 記録にない過去の事実(メンテナーがどのシェルで実行していたか)を、推測で補ったため |
| なぜ推測で補ったか | 記録がないことを、なかったこととして扱い、それを推測と書けば書いてよいと扱ったため。規則(AGENTS.mdの「情報源」)は、推測を明記すれば書くことを許していて、根拠を求めていない |
| なぜ確かめていない答えを分析に書いたか | なぜなぜ分析の答えを確かめた事実で書く手順(READMEの手順3)を、書く時点で確かめなかったため。手順を守ったかを確かめる段階がない |
| なぜメンテナーに尋ねなかったか | メンテナーが知っている事実は尋ねる、という決まりがなく、エージェントだけで記録を完成させようとしたため |

## 真因

規則が、根拠のない推測を「推測」と明記すれば書いてよいとしていて、推測を原因の分析や判断の前提にすることを止めていない。記録がなく分からないことを、分からないまま扱うか、知っている人(メンテナー)に尋ねる決まりもない。

## 対策

1. 現象への対応: 0023から根拠のない推測を除いて、メンテナーの指摘と履歴で確かめた事実だけで書き直した。
2. 規則(2026-11-10にメンテナーが承認した): AGENTS.mdの「情報源」に、次を加えた。
   - 推測は、根拠(確かめた事実)を示せるときだけ書き、その根拠を添える。
   - 記録がなく確かめられないことは、「記録がなく分からない」と書き、推測で埋めない。記録がないことを、なかったことの根拠にしない。
   - 分からないことや推測を、原因の分析・判断・記録の前提にしない。
   - メンテナーの環境や過去の操作など、メンテナーが知っている事実は、推測せずに尋ねる。尋ねる間も進められる作業は進め、その事実は分からないまま扱う。
3. 手順(2026-11-10にメンテナーが承認した): [README](README.md)の手順2(事実を確かめる)に、「記録がないことは、なかったことの根拠にしない。メンテナーが知っている事実は尋ねる」を加え、手順5(記録する)に、記録の前に、なぜなぜ分析の各段の答えに確かめた方法(ファイル、コマンド、メンテナーの指摘など)が書かれているかを見直すことを加えた。
4. 仕組み: 機械的な検査は加えない。理由: 推測かどうか、根拠があるかどうかは、文の意味によるため。2と3の規則と手順で扱う。

## 確かめ方

- これより後のincidentの記録で、なぜなぜ分析の各段の答えに、確かめた方法が書かれていること。
- 記録がない過去の事実を扱うときに、「分からない」と書くか、メンテナーに尋ねていること。
