# 0018: 0015の対策のあとも、合間の報告を英語で書いた

- 日付: 2026-11-09
- ステータス: 対策済み(対策はPR #62でマージした)
- 関連: [0001](0001-english-text-shown-to-maintainer.md)、[0005](0005-english-notes-between-tool-calls.md)、[0015](0015-english-reports-after-stop-hook.md)(同じ種類の異常の再発)

## 起きたこと

2026-11-09に、v0.2.0の版を上げる作業の途中で、エージェントは、ツール呼び出しの合間に「Next: bump the version and run the dependency age check.」と表示した。次に何をするかの報告で、AGENTS.mdでは日本語で書くもの(メンテナーへの説明・報告)にあたる。エージェントが、同じターンのうちに気づき、作業を止めてメンテナーに報告した。

確かめた事実(このセッションの会話の記録。assistantの文のうち、ラテン文字を含み、ひらがな・カタカナ・漢字を含まないものを検索した):

- 0015の対策(2026-11-05)のあと、日本語を含まない文は2つあった。
  - 2026-11-09 23:03(JST): 上の文。直前は、ツールの結果(コマンドの出力)と、英語のシステムの通知(タスクの道具の案内)だった。同じターンの、この文の前後の合間の報告は日本語だった。
  - 2026-11-09 23:20(JST): ワーカーのプロセスの再起動の通知への返答「No response requested.」。この返答は、再起動の通知と同じ時刻(ミリ秒まで同じ)に記録されていて、Stopのフック(`require-japanese-reply.sh`)は動いていない。エージェントが書いたものか、実行環境が加えたものかは、確かめられなかった。
- 対策のフックを作っている途中(2026-11-10 06:11と06:12(JST)。コンテナの再起動のあと)にも、合間の報告を英語で2回書いた(「The review that was re-run did finish before the restart. ...」「Next, update the countermeasures, status, and verification section in incident 0018.」)。直前は、コンテナの再起動の通知と、セッションの情報の通知(どちらも英語のシステムの文)、ツールの結果だった。フックはまだ登録していないため、止まらなかった。エージェントが、2回目のあとで気づいた。
- そのあと、v0.2.0のレビューの指摘に対応している途中(2026-11-10 07:26(JST))にも、合間の報告を英語で1回書いた(「Next, I'll append the manual-test items I didn't run to the Issue #59 body. ...」)。直前は、ツールの読み込みの結果と、タスクの道具の案内(どちらも英語)だった。エージェントが、その次の文で気づいた。対策のフックがマージされるまでは、規則だけに頼る状態が続いている。
- 対策のフックをマージした(PR #62)あとの2026-11-10 13:10(JST)にも、合間の報告を英語で1回書いた(「Template example links only (known false positives). Now I'll commit in three logical groups.」)。このセッションはマージの前に始まっていて、フックは働かなかった。Claude Codeは、セッションの開始時にフックの設定を読み込むためと考えられる(推測。新しいセッションでフックが働くことは、まだ確かめていない)。エージェントが、その次の文で気づいた。
- 同じセッションで、2026-11-10 13:20(JST)にも1回あった(「Next, I'll create the PR for the docs changes.」)。フックの働かないセッションでは、規則だけでは防げないことが続けて確かめられた。対策のフックが働くよう、新しいセッションに切り替えることを、メンテナーに提案した。

- ツール呼び出しの合間の文を確かめる仕組みはない。0005で加えたフック(合間の文に日本語がなければ、次のツールの呼び出しを拒否する)は、2026-11-01のメンテナーの判断で削除した。その判断では、合間の短いメモがやむを得ず英語になることを許容し、メンテナーへの説明・報告は必ず日本語で書くとした。
- 0015の対策1(振る舞い)は、メンテナーへの説明・報告は短くても日本語で書き、迷ったら日本語で書く、とした。仕組みの対策は、Stopのフックの変更だけだった。

## なぜなぜ分析

| なぜ | 答え(確かめた事実) |
| --- | --- |
| なぜ英語の報告が表示されたか | エージェントが、次の作業を告げる短い文を英語で書いたため |
| なぜ英語で書いたか | 英語の入力(ツールの結果とシステムの通知)が続いた直後に、短い文を書いたため。前後の報告は日本語で、規則は知っていた(入力の言語に引きずられたというのは推測) |
| なぜ表示のあとも止まらなかったか | ツール呼び出しの合間の文を確かめる仕組みがないため。0005のフックは、短いメモの英語を許容するという判断で削除し、0015でも規則だけで対応した |
| なぜ規則だけでは防げないか | 規則は書くときに思い出す必要があり、短い文ほど、メモ(英語でもよい)と報告(日本語)の区別を意識しないまま書くため。0005と0015で、同じことが繰り返し確かめられている |

## 真因

ツール呼び出しの合間の報告を日本語で書くことを、規則だけに頼っている。メモと報告の境目は、書く時点で区別されにくい。

## 対策

1. 現象への対応: その場でメンテナーに報告し、以後の報告を日本語で書いた。
2. 仕組み(2026-11-09にメンテナーが承認した。0005で削除した種類のフックを戻すため、2026-11-01の判断との関係を示して確かめた): すべてのツールの実行前に動くフック`require-japanese-note.sh`(PreToolUse)を加えた。ツール呼び出しを含むメッセージの文を会話の記録(`transcript_path`)から読み、ラテン文字を含み日本語を含まなければ、呼び出しを拒否して書き直しを求める。
   - 0005で記録を読む方式を採らなかった理由(記録は非同期に書かれ、最新のメッセージを含まないことがある。公式ドキュメント「Hooks reference」)には、入力の`tool_use_id`でそのツール呼び出しを含むメッセージを探し、見つからなければ止めない作りで対応した。2026-11-10 00:17(JST)に、このセッションの記録で、ツールの実行の時点で直前の文が書かれていること、英語の報告をしたときのツール呼び出しで拒否し、日本語の文のツール呼び出しで通すことを確かめた。約54MBの記録でも、約0.03秒で終わった。
   - 文は拒否の前に一度表示される(フックでは表示を止められない。0005の対策3と同じ)。
   - サブエージェントのツール呼び出しは、会話の記録にないため確かめない(サブエージェントの報告は、SubagentStopのフックで確かめている)。
3. 規則: AGENTS.mdの言語ルールの原則を改めた。ツール呼び出しの合間に書く文は、自分のためのメモも含めて日本語で書く(0005の許容をやめた)。考える過程の許容は残す。フックが見つけて書き直したものは、仕組みで直ったものとして、異常として作業を止める対象にしない(0005のとき、そのたびに止めて報告する負担が大きかったため)。フックで止まらなかった英語の文は、異常として扱う。

## 確かめ方

- `scripts/check_hooks.py`のサンプル入力で、日本語を含まない文のツール呼び出しを拒否し、日本語を含む文、文のないメッセージ、記号だけの文、記録にないツール呼び出し、記録のファイルがない場合を通すこと(CIで毎回確かめる)。
- 対策のマージのあとのセッションで、合間に英語の文を書いたときに、次のツールの呼び出しが拒否されること。
- Windows(Git Bash)での動作(`tail`と、Windowsの形のパスの`transcript_path`)は、未確認(メンテナーの環境で確かめるまで)。動かない場合は、何も止めない。
