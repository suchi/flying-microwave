# 0013: arm64のスモークテストを、タグを付けるまで試せず、リリースが2回続けて止まった

- 日付: 2026-11-03
- ステータス: 対策中(対策のPRがマージされていない)
- 関連: [計画0003](../plans/0003-v0.1.1-smoke-test.md)のD-4・D-7・D-9、[計画0001](../plans/0001-initial-implementation-plan.md)のD-23、[ADR-0016](../adr/0016-arm64-without-guarantee.md)

## 起きたこと

プレリリース`v0.1.1-alpha.1`(2026-11-03 07:33 JST)と`v0.1.1-alpha.2`(同 08:47 JST)のリリースのワークフローで、どちらもarm64のスモークテストのF-01が失敗し、下書きが作られなかった。

確かめた一次情報(リリースのワークフローの実行41538219628と41548092403のログ):

- alpha.1: arm64のランナー(`windows-11-arm`)で、製品の`SetForegroundWindow`が`false`を返し、テストが送ったキーが全画面のウィンドウに届かなかった。x64(`windows-2025`)では前面化もテストも成功した。
- alpha.2: alpha.1の失敗を受けて、前面に出せないときはクリックで確かめるようにした(D-7)。しかし、前面のウィンドウは別のプロセスの`Windows.UI.Core.CoreWindow`で、カーソルの下も製品の全画面のウィンドウではなかった。決めた条件のとおり、テストはクリックに切り替えずに失敗した。
- arm64のランナーでGUIを伴う処理を実行できるのは、リリースのワークフローだけである。PRのCIのWindowsのジョブはx64だけで(`ci.yml`)、リリースのワークフローはタグか既存のタグの手動実行でしか動かず、どちらもタグのコミットをビルドする。

## なぜなぜ分析

| なぜ | 答え(確かめた事実) |
| --- | --- |
| なぜリリースが2回続けて止まったか | arm64のスモークテストが、2回ともランナーの環境で入力が届かずに失敗したため |
| なぜ1回目の失敗のあとの修正も、リリースで失敗したか | 修正(D-7)が正しいかを確かめる手段が、次のタグしかなかったため。1回目のログからは、前面の画面が何かが分からず、修正は前面化の失敗だけを前提にしていた |
| なぜタグでしか確かめられなかったか | arm64のランナーを使うのはリリースのワークフローだけで、PRのCIや手動のジョブにarm64がないため |
| なぜその状態で、arm64で新しい検査を始めたか | 計画で「arm64のスモークテストは、プレリリースのタグで初めて動かす」と決めていた(D-4)。最初の1回は失敗を見込んでいたが、失敗したあとの修正を、タグなしで試す手段を用意していなかった |

## 真因

リリースのワークフローだけで動くランナー(arm64)に、環境に左右される検査(GUIを伴うスモークテスト)を加えるとき、タグを付けずに試す手段を用意せず、失敗したあとの修正もタグでしか確かめられなかった。

## 対策

1. 現象への対応(メンテナーの判断、D-9): arm64ではF-01を行わず、飛ばしたことをGitHub Actionsの注記で示す。arm64のリリースノートの節に、全画面のキーやクリックでの終了を確かめていないことを書く。版を`v0.1.1-alpha.3`にしてやり直す。
2. 真因への対策: AGENTS.mdの検証コマンドの段落に、「リリースのワークフローでだけ動く環境(arm64のランナーなど)に、環境に左右される検査を加えたり変えたりするときは、タグを付けずにその環境で試す手段(手動実行のジョブなど)を用意するか、試せないことと、失敗したときに新しい版のタグが要ることを、メンテナーに示して判断を得る」を加えた。
3. 仕組みによる対策(検討して採らなかった): CIにarm64の手動実行のジョブを加える案は、メンテナーに示したが、今回はarm64でF-01を扱わない判断となったため、採らなかった。arm64で環境に左右される検査を新しく加えるときに、2の規則に従って改めて判断する。

## 確かめ方

- `v0.1.1-alpha.3`のリリースのワークフローで、arm64のスモークテストが、F-01を飛ばした注記を出して成功し、下書きが作られること。
- 以後、arm64だけで動く検査を加えたり変えたりしたPRで、タグの前に試した記録か、試せないことについてのメンテナーの判断が、PRのまとめコメントに残っていること。
