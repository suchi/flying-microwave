# 0027: ログに何が書かれるかを、ログを書くコードを読まずに文書に書いた

- 日付: 2026-11-13
- ステータス: 対策中(現象への対応はPR #79でマージした。真因への対策は、2026-11-13にメンテナーが承認し、AGENTS.mdに加えた。マージのあとで、確かめ方で確かめる)
- 関連: [0014](0014-second-monitor-not-drawn.md)(ログの読み方をコードで確かめずに「分からない」と判断した。同じ種類の問題の再発)、[0024](0024-unfounded-guess-as-premise.md)(確かめていないことを、事実として書いた)、[計画0005](../plans/0005-v0.3.0-visuals-and-clock.md)の作業10とD-18

## 起きたこと

2026-11-12に、`v0.3.0-alpha.3`の版上げの作業で、計画0005の作業10に、終了の速さ(N-02)の判定の方法を書いた(コミット`25bea1d`)。その中に、数値を実機で測れない理由として「製品のログには、画面が消えた時刻が出ない」と書いた。2026-11-13に、PRを作る前の再レビュー(L-c)が、これはコードと合わないと指摘した。

確かめた事実:

- 製品は、終了を決めた時点で`exit:`の行を時刻付きで書き、その直後に全ウィンドウを隠す(`crates/app/src/saver.rs`の`decide`。328行目の`log!("exit: {event:?}")`と、336行目の`set_visible(false)`)。ログに出ないのは、画面が消えた時刻ではなく、入力した時刻である。実機で数値を測れないという結論は変わらない。
- エージェントは、この文を書くときに、製品のログを書くコードを読んでいなかった。直前に読んだのは、スモークテストのコード(`crates/smoke/src/windows.rs`。入力から画面が消えるまでを外から測って出す)だけだった(このセッションの作業の記録)。
- AGENTS.mdの「情報源」には、0014の対策として「ログから何かが『分からない』と判断するときは、そのログを書くコードを読み、何が書かれうるかを確かめてから判断する」がある。
- 同じ日(2026-11-12)に、PR #78のまとめコメントに「どこで止まっていたか(描画の中か、ほかの処理か)は、いまのログでは分かりません」と書いた。この判断も、そのときはログを書くコードを読まずにしていた。2026-11-13にコードで確かめたところ、製品は描画の試みを最初の数回だけ書く(`saver.rs`の750行目と835行目の`diag::first_few`)ため、4回目以降の描画でどこに時間がかかったかはログに出ず、判断は結果として正しかった。
- 誤った文は、PRを作る前のレビューで見つかり、`main`にはマージされていない。直した文は、コードの箇所を添えて書いた(コミット`0f3b229`)。

## なぜなぜ分析

| なぜ | 答え(確かめた事実) |
| --- | --- |
| なぜ誤った文を書いたか | 製品のログに何が書かれるかを、コードを読まずに推し量って書いたため。スモークテストが「入力から画面が消えるまで」を外から測っていることから、製品のログには画面が消えた時刻がないと考えた(このセッションの作業の記録。読んだのはスモークテストのコードだけ) |
| なぜ0014の規則(コードを読んでから判断する)が働かなかったか | 規則は「ログから何かが分からないと判断するとき」、つまりログを読んで分析する場面を対象にしている。今回は、計画の文書に理由を書く場面で、ログを読んでいなかったため、規則の場面だと認識しなかった(AGENTS.mdの「情報源」の文言) |
| なぜコミットの前に気づかなかったか | ログの中身についての文に、確かめた根拠(コードの箇所)を添える決まりがなく、確かめた文と確かめていない文の見分けがつかない。作成者が自分で気づくかに任されている。今回はレビューの段階で見つかった(再レビューの報告のL-c) |

## 真因

1. 0014の規則の対象が、ログを読んで判断する場面に限られている。ログに何が書かれるか、書かれないかを、文書・記録・報告に書く場面が含まれていない。
2. ログの中身についての文に、確かめた根拠(ログを書くコードの箇所)を添える決まりがない。そのため、確かめていない文を、作成者もレビューも見分けにくい。

## 対策

1. 現象への対応: 計画0005の作業10の文を、コードのとおり「入力した時刻がログに出ない」に直し、コードの箇所を添えた(コミット`0f3b229`)。PR #78のまとめコメントの「ログでは分かりません」の判断を、コードで確かめた(上の「確かめた事実」)。
2. 真因1と2への対策(2026-11-13にメンテナーが承認した): AGENTS.mdの「情報源」の0014の文を、次のように広げた。「ログに何が書かれるか・書かれないか、ログから何が分かるか・分からないかを、判断に使うときや、文書・記録・報告に書くときは、そのログを書くコードを読んで確かめ、その箇所(ファイルと関数名か行)を添える。行がないことも、事実として読む」。根拠の箇所を添えることで、レビューで確かめていない文を見分けられるようにする。
3. 仕組み: 機械的な検査は加えない。理由: 文がログの中身について述べているか、その内容がコードと合うかは、文の意味によるため。2の決まりと、レビューでの確認(今回も働いた)の2段で確かめる。

## 確かめ方

- 2のマージのあとで、ログの中身について書いた文書・記録・報告に、ログを書くコードの箇所が添えてあること。
- 以後のレビューで、ログの中身についての誤った記述が見つからないこと。
