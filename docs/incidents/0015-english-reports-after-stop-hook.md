# 0015: メンテナーへの報告を英語で書き、一部はフックでも止まらなかった

- 日付: 2026-11-05
- ステータス: 対策中(フックの変更は、メンテナーの承認を得た。2026-11-05。対策のPRがまだマージされていない)
- 関連: [0001](0001-english-text-shown-to-maintainer.md)、[0005](0005-english-notes-between-tool-calls.md)(同じ種類の異常の再発)、`.claude/hooks/require-japanese-reply.sh`

## 起きたこと

2026-11-04から11-05のセッションで、エージェントは、メンテナーへの報告や説明を、英語で書いて表示した。2026-11-05に、Stopのフック(`require-japanese-reply.sh`)が、ターンの最後の英語の報告を検出し、書き直しを求めた。

確かめた事実:

- 英語になったのは、ツール呼び出しの合間に書いた、作業の説明や結果の報告である。例:「The PR is still open and unmerged, so the merge didn't go through. I'll retry it once.」「Checks pass, and I've pushed the branch.」。AGENTS.mdは、合間に書くものでも、メンテナーへの説明・報告は日本語で書くと定めている。
- ターンの最後の報告も、2回英語だった。1回目(コミットしていない変更についての、Stopのフックへの返答)は、日本語のフックで止まらなかった。2回目は止まった。
- フックは、`stop_hook_active`が`true`のとき(ほかのStopのフックの求めで、ターンを続けているとき)は、何も確かめずに終わる(ループを防ぐため)。1回目は、別のStopのフック(コミットしていない変更を知らせるもの)の求めに応じた返答だったため、この条件で確かめられなかった。
- この期間、エージェントは、使用量の上限が近いことを受けて、短い文で作業を進めていた。英語の文は、その期間に集中している(推測を含む。時期の集中は会話の記録で確かめた)。

## なぜなぜ分析

| なぜ | 答え(確かめた事実) |
| --- | --- |
| なぜ英語の報告が表示されたか | エージェントが、合間の説明や報告を英語で書いたため |
| なぜ英語で書いたか | 0005の判断で、合間の短いメモは英語でも許容された。その例外と、メンテナーへの説明・報告(例外ではない)との境目を、短い文を書くときに区別しなかったため |
| なぜターンの最後の英語の報告が、1回はフックで止まらなかったか | フックが、ほかのStopのフックの求めでターンを続けているときは、確かめずに終わる作りだったため。ループを防ぐ条件が、確かめる対象まで外していた |
| なぜその抜けに気づかなかったか | フックを作ったとき(0001)は、Stopのフックが1つだけで、ほかのStopのフックの求めで続く場合がなかった。あとからStopのフックを加えたとき、組み合わせを確かめなかった |

## 真因

- 規則の例外(合間の短いメモ)と、例外でないもの(メンテナーへの説明・報告)の境目が、書く時点で意識されていない。規則だけに頼る部分が残っている(0005の対策4と同じ)。
- 確かめる仕組み(フック)を加えるときに、ほかのフックとの組み合わせで、確かめる対象から漏れる場合を洗い出さなかった。

## 対策

1. 振る舞い: ツール呼び出しの合間に書く文のうち、メンテナーへの説明・報告(何をしたか、結果、次に何をするか)は、短くても日本語で書く。英語でもよいのは、自分のためのメモに限る。迷ったら日本語で書く。
2. フックの変更(2026-11-05にメンテナーが承認した。`.claude/hooks/`の変更はセキュリティ設定のため): `stop_hook_active`が`true`のときも、日本語を確かめる。ループを防ぐため、同じセッション(`session_id`)で続けて求める回数に上限を設ける(一時フォルダーの、セッションごとの状態ファイルで数え、続けて2回まで。日本語を含む返答で数を戻す)。`scripts/check_hooks.py`に、ほかのStopのフックの求めで続けているときの英語の返答と、上限を超えたときのサンプル入力を加えた。

## 確かめ方

- フックを変えたあと、`stop_hook_active`が`true`で英語の返答のサンプル入力に、フックが書き直しを求めること(`scripts/check_hooks.py`)。上限を超えたときは、ターンを止めること。
- 以後のセッションで、メンテナーへの説明・報告が日本語で書かれていること(仕組みでは確かめられない部分は、規則に頼る)。
