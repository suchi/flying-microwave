# 0037: 合間の英語の文が会話の記録に残らず、日本語を求めるフックが止めなかった

- 日付: 2026-11-20
- ステータス: 対策中(2026-11-20に、メンテナーが対策の(1)を推奨どおりと判断した。計画0005のD-24。行うのは計画0005の作業10の5。(1)は実装したが、Claude Codeが考える過程を記録に書く振る舞いに頼るため、マージのあとで最初に始めるセッションで働くことを確かめるまで、対策済みにしない。AGENTS.mdの「検証コマンド」の節)
- 関連: [0018](0018-english-progress-note-again.md)(合間の英語の文の再発)、[0022](0022-note-hook-reads-transcript-too-early.md)(フックが記録を読む時点)、AGENTS.mdの「言語ルール」の原則

## 起きたこと

2026-11-20に、PR #88をマージする直前に、エージェントは、ツールの呼び出し(`merge_pull_request`)の前に英語の文を1つ書いた(「The trigger is `pull_request` only, … I'll merge with the head SHA pinned.」)。引用は、エージェント自身のコンテキストにある文で、会話の記録にはない(下の事実)。この文が本文としてメンテナーに表示されたのか、考える過程の表示だったのかは、記録から分からないため、メンテナーに尋ねている。合間の文に日本語を求めるフック(`.claude/hooks/require-japanese-note.sh`)は、この文を止めなかった。エージェントは、マージのあとの報告で知らせた。

AGENTS.mdの「言語ルール」は、合間の文も日本語で書くと定め、フックで止まらなかった英語の文を異常として扱うと定めている。

確かめた事実(このセッションの会話の記録。Claude Codeが`~/.claude/projects/`の下に書くJSONLのファイル):

- マージを呼んだメッセージ(`msg_011ChDeLqnbTvNwQRUC5fzKN`)の記録は、11015行(考える過程の塊、`thinking`)と11016行(ツールの呼び出し、`tool_use`)だけで、文の塊(`text`)がなかった。
- 11015行の考える過程の塊には、同じ内容の英語の文(「… so marking the PR ready won't start a run. I'm merging with the head SHA pinned next.」)があった。
- エージェントのコンテキストにある文(「The trigger is `pull_request` only, …」)は、記録のどの行にもなかった(`grep -n 'The trigger is \`pull_request\`'`で当たったのは、この検索のコマンド自身の行だけ)。
- フックは、記録の最後の200行から、ツールを呼んだメッセージの文の塊(`.type == "text"`)だけを読む(`require-japanese-note.sh`の71行。対策の前の版の行)。文の塊が記録にないため、見つけられなかった。
- 文の塊が記録に残らなかった理由は、Claude Codeが記録を書く仕組みによるもので、文書がなく分からない。この1回のほかに同じことが起きたかは、記録がなく分からない。

## なぜなぜ分析

1. なぜ英語の文を書いたか。
   - ツールの結果(英語)を確かめた直後に、そのまま英語で次の操作を説明した。日本語で書く規則は知っていたが、守れなかった(0018と同じ形)。
2. なぜフックが止めなかったか。
   - その文が、フックが読む会話の記録に、文の塊として残っていなかったため。
3. なぜ、記録に残らない文があることに気づかなかったか。
   - フックは、表示された文はすべて記録に残ると前提にしていた。0022で記録が遅れて書かれることは扱ったが、記録に残らないことは想定していなかった。
4. 真因: 表示される文をフックで確かめる仕組みが、会話の記録に頼っていて、記録に残らない文を確かめられない。また、英語のツールの結果のすぐあとで、英語で書いてしまう癖がある(0018)。

## 真因

- 日本語を確かめるフックは、会話の記録に残った文しか確かめられない。
- 英語のツールの結果を読んだ直後に、英語で書いてしまうことがある。

## 対策

2026-11-20に、メンテナーが(1)を採った(計画0005のD-24)。(2)の調査と、(3)(AGENTS.mdには加えない)は、案のとおりとする。(1)は計画0005の作業10の5で行う。

案:

1. 仕組み: `require-japanese-note.sh`が、文の塊のないメッセージで、考える過程の塊が英語だけのときにも知らせるようにする。今回は、表示されたかもしれない文と同じ内容が、考える過程の塊にあったため(この1回の例による。ほかにも同じかは、記録がなく分からない)。考える過程の英語は許容されている(AGENTS.mdの「言語ルール」)ので、止めるのではなく、日本語で書き直す必要があるかを確かめるよう求める形にする。フックの変更なので、承認が要る。
2. 調査: 文の塊が記録に残らない条件を、Claude Codeの文書とissueで確かめる。
3. 記録: AGENTS.mdには加えない。0018の対策(合間の文も日本語で書く規則)は、すでにある。

行ったこと:

- (1): `require-japanese-note.sh`は、ツールを呼んだメッセージに文の塊がなく、考える過程の塊がラテン文字だけで日本語を含まないとき、呼び出しを止めずに、PreToolUseの出力の`additionalContext`で1回だけ知らせる。知らせたメッセージのidは、拒否したときと同じ状態ファイルに残す。文の塊があるメッセージは、これまでどおり文の塊だけで判定する。`scripts/check_hooks.py`に試験の入力(`scripts/hook_samples/transcript-thinking.jsonl`)を加え、onboardingの6.3の説明を直した。
- (2): 2026-11-21に調べた。条件は確かめられなかった。
  - 公式の文書: 文の塊が会話の記録に残らない条件の説明はない(文書の写し`llms-full.txt`(2026-11-18に取得)を、`grep -n -i "transcript"`と`grep -n -i "thinking"`で検索し、記録・JSONL・要約に触れる行を読んだ)。変更履歴にある、記録からメッセージが落ちる不具合の修正は、`CLAUDE_CODE_TRANSCRIPT_LOCAL_GC`を有効にしたときのもので、このセッションのClaude Codeのプロセスの環境には、この変数がなかった(`/proc/<pid>/environ`で確かめた)。
  - 会話の記録の値: マージを呼んだメッセージの2行は、どちらも`model`が`claude-opus-5-5`、`version`が`2.1.329`だった。
  - 公式リポジトリ(anthropics/claude-code)のissue: 似た報告が複数ある(`gh api -X GET search/issues`で`is:issue repo:anthropics/claude-code transcript text block missing`などを検索した)。どれも利用者の報告(`author_association`が`NONE`)で、メンテナーが原因を示したものは、検索の結果の本文からは見つからなかった(コメントは読んでいない)。#94251は、2.1.270から、ツールを呼ぶ前の文の塊の多くが記録に書かれない(画面には表示される)という報告。#94336は、ツールの呼び出しのあいだの文の塊が記録に残らず、その位置に文の要約が考える過程の塊として残ったという報告(別のモデルでの報告で、Opusでは見られなかったとある)。#97504は、利用者に向けた文を、モデルが文の塊ではなく考える過程の塊に書くことがある(利用者には表示されない)という報告。
  - 分かったこと: 今回の形(文の塊がなく、考える過程の塊に同じ内容がある)は、「記録に書かれなかった」(#94251、#94336)と「もともと考える過程に書かれた」(#97504)のどちらでも起きうる。どちらかは、メンテナーへの質問(本文として表示されたか)の答えがないと分からない。対策(1)のフックは、どちらの場合も、考える過程の塊が英語だけのメッセージとして知らせる。

## 確かめ方

- 対策1: `scripts/check_hooks.py`の試験の入力で、文の塊がなく、考える過程の塊が英語だけのメッセージを、フックが知らせること。
- このあとのセッションで、フックが止めなかった英語の合間の文がないこと(メンテナーの指摘か、エージェントの見直しで確かめる)。
