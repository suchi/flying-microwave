# 0042: 規則を変えたときに、同じ説明を書いたほかの文書を直し漏らした(再発)

- 日付: 2026-11-21
- ステータス: 対策中(対策は計画0005のD-29の(3)とD-30の(6)で採り、そのあとのPRで行う)
- 関連: [0034](0034-incident-list-test-skipped.md)(スクリプトのテストを実行する条件を加えた異常)、[0038](0038-release-notes-not-updated-after-hardware-check.md)(条件を広げた対策)

## 起きたこと

2026-11-21に、incident 0038〜0041の対策のPRを作る前の再レビューで、スクリプトのテストを実行する条件が、`docs/development/onboarding.md`と`.claude/commands/babysit-pr.md`で古いままだと指摘を受けた。同じ種類の漏れは前にもあったので、AGENTS.mdの「進め方」の、同じ種類の問題の再発に当たる。

確かめた事実:

- 2026-11-21のPRでは、文書だけの変更でもスクリプトのテストを実行する条件に、`CHANGELOG.md`と`docs/development/hardware-check-*.md`を加えた(計画0005のD-28の(3))。直したのはAGENTS.mdと`.claude/commands/commit.md`だけで、同じ条件を書いた`onboarding.md`(開発の手順の節)と`babysit-pr.md`(手順3b)は古いままだった(`grep -rn "docs/README.md\`を変え" --include=*.md .`で見つかった)。
- 2026-11-20にも、incident 0034の対策でAGENTS.mdと`commit.md`に同じ条件を加えたとき、`onboarding.md`と`babysit-pr.md`への書き添えが漏れ、再レビューで見つかった(計画0005の作業10の5に「2026-11-20の再レビューで見つかった食い違い」として登録した)。

## なぜなぜ分析

1. なぜ、ほかの文書を直し漏らしたか。
   - 決定(D-28の(3))に挙がったファイルだけを直し、同じ説明がほかにあるかを探さなかった(推測。根拠は、この変更の差分にgrepの記録がなく、直したのが決定に挙げたファイルだけだったこと)。
2. なぜ、同じ説明を探さなかったか。
   - 同じ規則を書いた文書が4つあることを、規則と手順のどこにも書いておらず、変えるときに探す段もない(AGENTS.md、`commit.md`、`babysit-pr.md`、`onboarding.md`を読んで確かめた)。
3. なぜ、前の漏れのあとで再発したか。
   - 前の漏れ(2026-11-20)は、その2つの文書に書き添えて直しただけで、同じ説明がほかにもあることを見つける仕組みを作らなかった。
4. 真因: 同じ規則の説明が複数の文書にあり、それらがそろっているかを確かめる仕組みがない。

## 真因

- 同じ規則(スクリプトのテストを実行する条件)の説明が4つの文書にあり、そろっているかを確かめる仕組みがない。

## 対策

行ったこと:

- `onboarding.md`と`babysit-pr.md`の条件を、AGENTS.mdと同じにした(2026-11-21のメンテナーの判断。計画0005のD-29の(1))。

採った案(2026-11-21にメンテナーが採った。計画0005のD-29の(3)。そのあとのPRで行う):

1. 仕組み: スクリプトのテストを実行する条件のパスの一覧が、AGENTS.md、`.claude/commands/commit.md`、`.claude/commands/babysit-pr.md`、`docs/development/onboarding.md`で同じであることを確かめるテストを、`scripts/`に加える。

## その後の再発

- 2026-11-21に、文書の整理(計画0005のD-30)で、AGENTS.mdの「ドキュメント」の節の個人情報の規則を広げたとき、同じ規則を書いた`docs/development/onboarding.md`(「個人情報」の箇条)、`docs/README.md`(冒頭)と、ADRの上書き禁止を書いた`.agents/skills/adr/SKILL.md`への書き添えが漏れ、PRを作る前のレビューで見つかった。対策のテスト(D-29の(3))は、まだ加えていなかった。テストが見るのはスクリプトのテストの条件だけなので、加えていても、この漏れは見つからなかった。
- 対応: 3つの文書に書き添えた。
- 真因(同じ規則を写した文書がどれかを、規則と手順のどこにも書いておらず、そろっているかを確かめる仕組みもない)への対策として、2026-11-21に、メンテナーが次の案を採った(計画0005のD-30の(6))。
  1. AGENTS.mdに、規則を写している文書の一覧を置く。
  2. D-29の(3)のテストを、その一覧の規則(スクリプトのテストの条件と、個人情報の規則の決まった語)が、写しの文書すべてにあるかを確かめる形に広げる。
  - どちらも、計画0005の作業10の5の、0042の対策のPRで行う。採らなかった案は、`.claude/commands/commit.md`に、規則を変えたら同じ言葉を`git grep`で探す段を加えること。手順だけでは、守られないと効かないため。

## 行ったこと

- AGENTS.mdに「規則の写し」の節を加え、写しを持つ規則(スクリプトのテストの条件と、個人情報の規則)ごとに、決まった語と写しを置く文書を表にした。
- `scripts/test_rule_copies.py`を加えた。このテストは、表を読み、決まった語が写しの文書すべてにあるかを確かめる。写しの1つ(`.claude/commands/babysit-pr.md`)から決まった語(`CHANGELOG.md`)を消した複製で、テストが失敗することを確かめた。

## 確かめ方

- テストを加えたあとで、条件を1つの文書だけで変えると、テストが失敗すること。
