# 0001: メンテナーに英語の文章が表示された

- 日付: 2026-11-01
- ステータス: 対策中(フックを加えるPRがマージされていない)

## 起きたこと

Claude Code on the Webで、メンテナーに英語の文章が表示された。メンテナーが示した文は、エージェントがその直前の作業で考えた内容(スパイクのワークフローが再実行されたことと、今後の進め方)と一致した。エージェントは、作業の中でツールを実行するときの説明文も英語で書いていた。

あわせて、2つ目の異常が起きた。英語の表示について問われたエージェントは、確かめないまま、システムの通知であると説明した。

同じ種類の問題(英語の返答)は、以前にも起きていた。そのときは、「返答の言語が直前の入力の言語に引きずられた」ことを原因として、サブエージェントへの依頼文と報告を日本語にする規則を加えた(PR #8)。それでも再発した。

## なぜなぜ分析(英語の表示)

| なぜ | 答え |
| --- | --- |
| なぜ英語が表示されたか | エージェントが英語で書いた文章が表示されたため(事実: メンテナーが示した文と、エージェントが考えた内容が一致した)。考える過程を誰がどのように要約して表示するかは、確かめていない(推測: 考える過程が英語なので、その要約も英語になった) |
| なぜ英語で書いたか | 日本語にしていたのは、返答・文書・サブエージェントへの依頼文と報告だけで、考える過程とツールの説明文は英語のままにしていたため(事実) |
| なぜそう分けていたか | その2つはメンテナーに見えない内部のものだと思い込み、実際の表示を確かめていなかったため |
| なぜ確かめなかったか | 言語ルールが「対象の一覧」の形で書かれていて、一覧にない出力は対象外と解釈したため(事実: AGENTS.mdの言語ルールの表と、その下の箇条)。PR #8で分析したときも、「直前の入力の言語に引きずられる」という途中の原因で止め、一覧に項目を足すだけにした |
| なぜ途中で止めたか | 異常が起きたときに真因まで掘り下げる手順がなく、見えた現象への対策で済ませる進め方になっていたため |

## なぜなぜ分析(確かめずに説明した)

| なぜ | 答え |
| --- | --- |
| なぜ誤った説明をしたか | 表示の経路を確かめないまま、思い当たる原因(システムの通知)を事実として答えたため |
| なぜ確かめずに答えたか | 「確かめた事実と推測を区別する」規則(AGENTS.mdの「情報源」)を、調べ物の結果にだけ当てはめ、自分の振る舞いについての説明には当てはめていなかったため |
| なぜそう当てはめていたか | 異常について問われたときに、まず止めて事実を確かめる、という手順がなかったため。上の分析の5段目と同じ根である |

## 真因

1. 言語ルールが、原則ではなく、出力の種類の一覧で書かれていた。新しい表示の経路が現れるたびに漏れる。
2. 異常への対応の手順(止める、事実を確かめる、真因まで掘り下げる)がなかった。
3. 対策が規則の文言に頼っていて、守られていないことに気づく仕組みがなかった。PR #8の対策が再発を防げなかったのも、このためである。

## 対策

1. 言語ルールを原則に改めた。ユーザーに表示されうる文章は、考える過程とツールの説明文も含めて、すべて日本語で書く(AGENTS.mdの「言語ルール」)。
2. 異常への対応の手順を定めた。止める、事実を確かめる、なぜなぜ分析、真因への対策、記録(AGENTS.mdの「進め方」と、この一覧の`README.md`)。
3. 仕組みでの対策(2026-11-01にメンテナーの承認を得て、別のPRで加えた。[オンボーディングの6.3](../development/onboarding.md#63-フック)のrequire-japanese-description.shとrequire-japanese-reply.sh)。既存のフックの理由の文も日本語にした。Claude Codeのフックで、次を確かめられる(公式ドキュメント「Hooks reference」で2026-11-01に確かめた)。
   - PreToolUseのフックの入力には、ツールの`tool_input`が含まれ、Bashでは`description`(ツールの説明文)が入る。フックは`permissionDecision`を`deny`にして、理由を添えて呼び出しを拒否できる。
   - Stopのフックの入力の`last_assistant_message`で、返答の文面を確かめられる。
   - 考える過程は、どのフックの入力にも含まれない(確かめた範囲)。このため、考える過程は仕組みでは確かめられず、原則の規則に頼る。
   - 説明文の確認の対象は、BashとAgentのツールに限る。WindowsのPowerShellのツールなど、ほかのツールの説明文は確かめていない(既存のblock-dangerous-git.shも、Bashだけが対象である)。

## 確かめ方

- フックを入れたあとは、日本語を含まないツールの説明文がPreToolUseのフックで拒否されること。返答は、Stopのフックで検出して日本語での書き直しを促す(Stopのフックは、終了コード2で「Claudeが止まるのを防ぎ、会話を続けさせる」だけで、表示を止めることはできない。公式ドキュメント「Hooks reference」のStopの説明)。
- メンテナーに英語の文章(コード・識別子・コマンド・英語の原文の引用、規則で英語と定めた対象を除く)が表示されないこと。
- 次に異常が起きたとき、この手順で記録されること。
