# 0023: タグの前に件名を確かめるコマンドが、Windowsのコマンドプロンプトで動かなかった

- 日付: 2026-11-10
- ステータス: 対策中(手順の対策は、メンテナーの判断を待っている)
- 関連: [0016](0016-tag-before-merge.md)(件名を確かめるコマンドを加えた対策)、[0024](0024-unfounded-guess-as-premise.md)(この記録を書く途中の異常)、`.claude/commands/merge-pr.md`の手順3、[オンボーディング](../development/onboarding.md)の5章

## 起きたこと

2026-11-10に、`v0.3.0-alpha.1`のタグ付けを依頼した。メンテナーが、Windowsのコマンドプロンプト(cmd)で、件名を確かめるコマンド`git log -1 --format='%h %s' <SHA>`を実行したところ、`fatal: ambiguous argument '%s'': unknown revision or path not in the working tree.`で失敗した。タグは付けていない。エージェントは、引用符の要らない`git log -1 --oneline <SHA>`に置き換えて、依頼し直した。

確かめた事実:

- cmdは、単引用符(`'`)を引用符として扱わない。そのため、`'%h`と`%s'`が別々の引数になり、`%s'`がリビジョンとして解釈された(エラーの文で確かめた)。
- このコマンドの形は、マージの手順(`.claude/commands/merge-pr.md`の手順3。incident 0016の対策)が指定している。エージェントは、その形のまま、シェルを指定せずに依頼した。依頼のコードブロックは`bash`にしていた。
- オンボーディングの5章は、Windowsでのコマンドを PowerShell で実行するとしている。マージの手順と、メンテナーへの依頼の手順(AGENTS.mdの「進め方」)には、どのシェルで実行するかの決まりがない。
- メンテナーは、これまでのタグ付けも、エージェントの依頼に従ってcmdで行っていた。bashを前提にしたコマンドを依頼されたのは、今回が初めてだった(メンテナーの指摘)。
- マージの手順に、この形の件名の確認が入ったのは、コミット`a1e59a3`(2026-11-10 13:10 JST)で、`v0.2.0`のタグ付け(そのマージは10:43 JST)より後である(`git log -S`で確かめた)。この形でタグ付けを依頼したのは、今回が初めてである。
- エージェントは、この記録を書く途中で、根拠なしに「cmdで実行したのは今回が初めて」と推測し、それを前提にしようとした。メンテナーの指摘で取り消した([0024](0024-unfounded-guess-as-premise.md))。

## なぜなぜ分析

| なぜ | 答え(確かめた事実) |
| --- | --- |
| なぜコマンドが失敗したか | cmdが単引用符を引用符として扱わず、`--format`の値が2つに分かれたため |
| なぜcmdで動かない形を依頼したか | マージの手順(`a1e59a3`で加えた)が、bash系のシェルの引用の形でコマンドを指定していて、エージェントがそれをそのまま写して依頼したため。これまでの依頼は、cmdで動く形だった(メンテナーの指摘) |
| なぜ手順の形のまま写したか | マージの手順にも、AGENTS.mdの依頼の手順にも、メンテナーに依頼するコマンドをどのシェルで動く形にするかの決まりがなく、メンテナーがcmdを使うことも書かれていなかったため。手順にこの形を加えたとき(`a1e59a3`)に、メンテナーのシェルで動くかは確かめられていない(そのときの記録はコミットだけで、シェルについての記述はない) |

## 真因

メンテナーに依頼するコマンドを、メンテナーの環境のシェル(cmd、PowerShell、Git Bash)のどれでも動く形にするか、シェルを指定するかの決まりがなかった。

## 対策

1. 現象への対応: 引用符の要らない`git log -1 --oneline <SHA>`に置き換えて、依頼し直した。
2. 手順(メンテナーの判断を待っている):
   - マージの手順(`.claude/commands/merge-pr.md`の手順3)の件名の確認を、`git log -1 --oneline <SHA>`にする(シェルによらず動く。表示は短いSHAと件名で、確かめる内容は変わらない)。
   - AGENTS.mdの「進め方」の、メンテナーに依頼する手順の箇条に、次を加える: メンテナーに実行を依頼するコマンドは、cmd・PowerShell・Git Bashのどれでも同じに動く形(シェルの引用符や変数の展開に頼らない形)にする。そうできないときは、実行するシェルを指定する。
3. 仕組み: 機械的な検査は加えない。理由: 依頼の文はリポジトリのファイルでなく、会話の中で書くため。手順の文書のコマンドは、2の変更で直す。
