# 0023: タグの前に件名を確かめるコマンドが、Windowsのコマンドプロンプトで動かなかった

- 日付: 2026-11-10
- ステータス: 対策中(手順の対策は、メンテナーが示した方針で行い、2026-11-10にPR #70でマージした。確かめ方は、まだ確かめた記録がない。2026-11-13に、マージのあとのステータスの更新が漏れていたことが分かり、直した([0029](0029-incident-status-stale-again.md)))
- 関連: [0016](0016-tag-before-merge.md)(件名を確かめるコマンドを加えた対策)、[0024](0024-unfounded-guess-as-premise.md)(この記録を書く途中の異常)、`.claude/commands/merge-pr.md`の手順3、[オンボーディング](../development/onboarding.md)の5章

## 起きたこと

2026-11-10に、`v0.3.0-alpha.1`のタグ付けを依頼した。メンテナーが、Windowsのコマンドプロンプト(cmd)で、件名を確かめるコマンド`git log -1 --format='%h %s' <SHA>`を実行したところ、`fatal: ambiguous argument '%s'': unknown revision or path not in the working tree.`で失敗した。タグは付けていない。エージェントは、引用符の要らない`git log -1 --oneline <SHA>`に置き換えて、依頼し直した。

確かめた事実:

- cmdは、単引用符(`'`)を引用符として扱わない。そのため、`'%h`と`%s'`が別々の引数になり、`%s'`がリビジョンとして解釈された(エラーの文で確かめた)。
- このコマンドの形は、マージの手順(`.claude/commands/merge-pr.md`の手順3。incident 0016の対策)が指定している(ファイルで確かめた)。エージェントは、その形のまま、シェルを指定せずに依頼した。依頼のコードブロックは`bash`にしていた(このときのエージェントの依頼の文による)。
- オンボーディングの5章は、Windowsでのコマンドを PowerShell で実行するとしている。マージの手順と、メンテナーへの依頼の手順(AGENTS.mdの「進め方」)には、どのシェルで実行するかの決まりがない。
- メンテナーは、これまでのタグ付けも、エージェントの依頼に従ってcmdで行っていた。bashを前提にしたコマンドを依頼されたのは、今回が初めてだった(メンテナーの指摘)。
- マージの手順に、この形の件名の確認が入ったのは、コミット`a1e59a3`(2026-11-10 13:10 JST)で、`v0.2.0`のタグ付け(そのマージは10:43 JST)より後である(`git log -S`で確かめた。分かるのは手順に入った時期だけである)。それより前の依頼の内容は、記録がなく分からない。bashを前提にした依頼が今回が初めてだったことは、メンテナーの指摘による。
- この記録を書く途中で、記録にない過去の事実を根拠なしに推測し、前提にしようとしたため、取り消した([0024](0024-unfounded-guess-as-premise.md))。

## なぜなぜ分析

| なぜ | 答え(確かめた事実) |
| --- | --- |
| なぜコマンドが失敗したか | cmdが単引用符を引用符として扱わず、`--format`の値が2つに分かれたため |
| なぜcmdで動かない形を依頼したか | マージの手順(`a1e59a3`で加えた)が、bash系のシェルの引用の形でコマンドを指定していて(ファイルで確かめた)、エージェントがそれをそのまま写して依頼したため。これまでの依頼は、cmdで動く形だった(メンテナーの指摘) |
| なぜ手順の形のまま写したか | マージの手順にも、AGENTS.mdの依頼の手順にも、メンテナーに依頼するコマンドをどのシェルで動く形にするかの決まりがなく、メンテナーがcmdを使うことも書かれていなかったため。手順にこの形を加えたとき(`a1e59a3`)に、メンテナーのシェルで動くかを確かめたかは、記録がなく分からない(コミットの本文にシェルについての記述はない) |

## 真因

メンテナーに依頼するコマンドを、メンテナーの環境のシェル(cmd、PowerShell、Git Bash)のどれでも動く形にするか、シェルを指定するかの決まりがなかった。

## 対策

1. 現象への対応: 引用符の要らない`git log -1 --oneline <SHA>`に置き換えて、依頼し直した(このあとのレビューで、`--no-decorate`も付けることにした。2を参照)。
2. 手順(2026-11-10にメンテナーが方針を示した): メンテナーは、依頼されたコマンドを、coreutilsの入ったcmdで実行するのがいちばんやりやすく、これを優先する。依頼するコマンドは、cmdでそのまま動く形にし(coreutilsのコマンドは使ってよい)、cmdではできないときや手間が多いときは、PowerShellかGit Bashでの実行を、シェルを示して勧める(cmdに限るものではない)。
   - AGENTS.mdの「進め方」の、メンテナーに依頼する手順の箇条に、この方針を加えた。
   - マージの手順(`.claude/commands/merge-pr.md`の手順3)の件名の確認を、引用符の要らない`git log -1 --no-decorate --oneline <SHA>`にした(表示は短いSHAと件名で、確かめる内容は変わらない。`--no-decorate`は、端末でブランチ名やタグの括弧が付いて、期待する表示と違って見えないようにするため)。
3. 仕組み: 機械的な検査は加えない。理由: 依頼の文はリポジトリのファイルでなく、会話の中で書くため。手順の文書のコマンドは、2の変更で直した。
