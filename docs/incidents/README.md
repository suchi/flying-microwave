# 異常の記録(なぜなぜ分析)

- ステータス: 採用(2026-11-01)
- 関連: [AGENTS.md](../../AGENTS.md)の「進め方」

開発の中で起きた異常について、真因と対策を記録する。目的は再発の防止である。

## 異常への対応の手順

トヨタ生産方式では、異常が起きたら止めて異常を明らかにし(自働化)、「なぜなぜ」を繰り返して真因を追求し、対策を講じる。本プロジェクトの手順はこれに倣う。

1. 止める: 異常に気づいたら、その作業を止めて、ユーザーに知らせる。異常とは、規則に反する出力、コマンドやツールの想定外の挙動、メンテナーやレビューからの問題の指摘などである。
2. 事実を確かめる: 何が起きたかを、ログ・ソース・設定・公式ドキュメントなどの一次情報で確かめる。推測は推測として分ける。
3. なぜなぜ分析: 「なぜ」を繰り返し、対策を打てば再発しなくなる原因(真因)までさかのぼる。各段の答えは、確かめた事実で書く。
4. 真因に対策する: 目の前の現象を直すだけで終わらせない。規則・手順・仕組みのどれを変えれば同じ種類の異常が起きなくなるかを考え、ユーザーの承認を得て変える。
5. 記録する: この一覧に、番号付きで記録する。

## 記録の書き方

ファイル名は`NNNN-<異常の要約>.md`(4桁の連番。要約は英語のkebab-case)。本文には次を書く。

- 起きたこと: 日付、現象、気づいたきっかけ。
- なぜなぜ分析: 各段の「なぜ」と答え(確かめた事実)。
- 真因: 対策の対象とした原因。
- 対策: 変えた規則・手順・仕組みと、その変更(PR)。
- 確かめ方: 対策が効いたことを、何で確かめるか。
