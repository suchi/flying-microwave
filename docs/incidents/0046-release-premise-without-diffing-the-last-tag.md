# 0046: 前の版のタグからの変更を確かめずに、正式なリリースの中身を「試作版と同じ機能」と書いた

- 日付: 2026-11-27
- ステータス: 対策中(手順の対策は、2026-11-27にメンテナーが承認し、計画0001の7.2の手順1に加えた。`v0.3.0`の版上げのPRのマージを待っている)
- 関連: 計画0001の7.2、計画0005のD-49、[0024](0024-unfounded-guess-as-premise.md)、[0031](0031-requested-publishing-an-already-published-release.md)

## 起きたこと

2026-11-27に、メンテナーが、正式なリリース`v0.3.0`を実機での確認を待たずに出すと決めた(計画0005のD-49)。エージェントは、その記録、CHANGELOGの`v0.3.0`の節、onboarding、レビューの依頼文に、`v0.3.0`は`v0.3.0-alpha.5`と同じ機能で、そのあとの変更はアイコンだけだと書いた。版上げのPRの前の本格的なレビューが、`alpha.5`のタグのあとに、描画まわりの依存の更新が入っていると指摘した(指摘H-1)。同じ種類の問題(確かめていない前提を、判断と記録の前提にした。[0024](0024-unfounded-guess-as-premise.md)、[0031](0031-requested-publishing-an-already-published-release.md))の再発に当たるため、異常として扱う。

確かめた事実:

- `git log --oneline --no-merges v0.3.0-alpha.5..92a73e3 -- crates Cargo.toml Cargo.lock build.rs packaging assets`は、5つのコミットを返した。新しいアイコン(`91e67f9`)とその文書(`c8c7414`)、resvgの更新(`8911471`)、依存の更新(`a551587`)、アイコンの空白だけの作り直し(`3f9cd1e`)である。
- `git diff v0.3.0-alpha.5 92a73e3 -- Cargo.lock`で変わった版は、wgpu 30.0.1から30.0.2、resvg と usvg 0.49.0から0.50.0、svgtypes 0.16.1から0.16.2、toml 1.2.0から1.2.1などだった。依存の更新は、2026-11-24にPR #95とPR #96でマージした(Dependabotが作ったPR)。
- CHANGELOGの「未リリース」の節には、アイコンの変更だけがあり、依存の更新はなかった(`8b5016e`の前のCHANGELOG.mdの7〜11行)。
- エージェントは、CHANGELOGの節を書くときと、D-49を記録するときに、前の版のタグからの変更を`git log`や`Cargo.lock`の差分で確かめなかった(この日の作業の記録による)。
- メンテナーの判断の理由は、「少なくとも動いている」(`v0.3.0-alpha.4`の実機での確認)だった。依存の更新は実機で一度も動かしていなかったが、そのことを示していなかった。依存の更新を示して改めて尋ね、メンテナーは、このまま出すと決めた(D-49に書き足した)。

## なぜなぜ分析

1. なぜ、「`alpha.5`と同じ機能」と書いたか。
   - CHANGELOGの「未リリース」の節を、前の版からの変更の一覧として扱ったため。節にあったのはアイコンの変更だけだった(上の「確かめた事実」)。
2. なぜ、「未リリース」の節に依存の更新がなかったか。
   - 依存の更新はDependabotのPRでマージし、CHANGELOGに項目を書いていなかったため(PR #95とPR #96のコミット`a551587`と`8911471`の変更は、`Cargo.lock`と`crates/*/Cargo.toml`だけで、CHANGELOG.mdはない。`git show --stat a551587 8911471`で確かめた)。
3. なぜ、前の版のタグからの変更を確かめなかったか。
   - リリースの手順(計画0001の7.2)に、前の版のタグからの変更を一次情報で一覧にし、CHANGELOGの節と照らす段がなかったため(7.2を読み直して確かめた)。メンテナーに判断を仰ぐときに、その一覧を示す段もなかった。
4. 真因: リリースの中身を、前の版のタグからの差分という一次情報で確かめる段がなく、CHANGELOGの「未リリース」の節に頼っていた。

## 真因

- リリースの手順に、前の版のタグからの変更(コミットと依存の版)を一覧にしてCHANGELOGの節と照らし、判断を仰ぐときにその一覧を示す段がない。

## 対策

行ったこと:

- `v0.3.0`のCHANGELOGの節、計画0005のD-49と「v0.3.0のリリースの記録」、onboardingに、依存の更新を含むことと、実機で確かめていないことを書いた。
- 依存の更新を示して、メンテナーに改めて判断を仰いだ(2026-11-27。このまま出す)。

案(手順の文書の変更なので、メンテナーの承認が要る。2026-11-27に、メンテナーが(1)を採った):

1. 手順: 計画0001の7.2の手順1に、前の版のタグからの変更(`git log <前のタグ>..main`と、`Cargo.lock`の差分)を一覧にしてCHANGELOGの節と照らし、メンテナーに判断を仰ぐときはその一覧を示すことを加える。
2. 仕組み: 採らない。依存の更新ごとにCHANGELOGの項目を求める検査は、利用者に関わらない更新まで項目にすることになり、どの更新を書くかの判断を機械では決められない。

## 確かめ方

- 次の版上げのPRで、前の版のタグからの変更の一覧を作り、CHANGELOGの節と照らしたことを、PRの本文かまとめコメントに書くこと。
