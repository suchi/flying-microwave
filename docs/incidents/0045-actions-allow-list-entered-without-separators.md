# 0045: 公開の手順の一覧が許可するアクションの書き方を示さず、CIが始まらなくなった

- 日付: 2026-11-27
- ステータス: 対策済み(手順の一覧の直しは、2026-11-27にPR #108でマージした。設定の直し(1)は、同じ日にメンテナーが行い、そのあとのPR #108のCIの実行(45954132658)でジョブが始まり、成功したことを確かめた。規則の対策(2)は、同じ日にメンテナーが承認し、AGENTS.mdの「進め方」に加えて、2026-11-27にPR #109でマージした)
- 関連: [公開の手順の一覧](../development/publication-checklist.md)の1.1、[記録0006](../reviews/0006-pre-publication-threat-recheck.md)、計画0005のD-47、計画0006、AGENTS.mdの「進め方」(メンテナーへの依頼)

## 起きたこと

2026-11-27に、計画0006のPR #108のCI(`ci.yml`)の実行が`startup_failure`で終わり、ジョブが1つも始まらなかった(実行45952195315)。エージェントは、PRのチェックの一覧にCIのジョブがないことから気づいた。メンテナーが実行のページのエラーの文と、Settings → Actions → General の設定の欄の中身を知らせた。

確かめた事実:

- エラーの文(メンテナーが貼ったもの)は、`actions/checkout@3d3c42e…`、`swatinem/rust-cache@d1527c8…`、`actions/upload-artifact@cf430e0…`が許されていないとし、許すパターンとして、6つの名前を改行で挟んだ1つの文字列を示していた。
- 設定の欄は、6つの名前を1行に1つずつ書き、最後の名前のあとにコンマがあった(メンテナーが貼ったもの)。
- GitHubの文書(「Managing GitHub Actions settings for a repository」の「Allow or block specified actions and reusable workflows」)は、パターンをコンマで区切ること(Use , to separate patterns)と、アクションを`OWNER/REPOSITORY@TAG-OR-SHA`の形で書き、`*`を使えることを示している(`docs.github.com`のページを取得して読んだ)。
- 公開の手順の一覧の1.1(`d540dc9`の時点)は、許すアクションを、名前だけの箇条書き(`actions/checkout`など)で示し、欄への書き方(区切りと`@`以降)を書いていなかった(`git show d540dc9:docs/development/publication-checklist.md`で確かめた)。
- 再点検の記録0006を作ったときのレビュー(計画0005のD-47の対策のレビュー)は、画面の項目名がGitHubの文書と合うことを確かめたが、欄に入れる値の書き方は確かめていなかった(そのレビューの報告の「問題なしと確かめたもの」による)。
- 設定を変えたのは公開のとき(2026-11-25から27の間。正確な時刻は記録がなく分からない)で、そのあと、`ci.yml`はPR #108まで一度も動いていなかった(ワークフローの実行の一覧で確かめた。2026-11-25 19:48 JSTのmainの実行のあとは、PR #108の実行が最初)。

## なぜなぜ分析

1. なぜ、CIが始まらなかったか。
   - 許すアクションの欄が改行で区切られ、全体が1つのパターンになり、どのアクションにも当たらなかったため(エラーの文と、GitHubの文書の区切りの決まり)。
2. なぜ、改行で区切って入れたか。
   - 手順の一覧が、名前を1行に1つずつの箇条書きで示し、区切りと書き方を書いていなかったため(`d540dc9`の手順の一覧)。
3. なぜ、手順の一覧に書き方を書かなかったか。
   - 手順の一覧を作るときに、画面の項目名は公式の文書で確かめたが、欄に入れる値の書き方は確かめなかったため。レビューも、項目名だけを照らした(上の「確かめた事実」)。メンテナーに設定の値を入れてもらうときに、公式の文書で書式を確かめ、そのまま貼れる値を示すことを求める規則も手順もない(AGENTS.mdの「進め方」のメンテナーへの依頼の箇条を読み直して確かめた。コマンドの形(cmdで動くこと)は定めているが、設定の画面の値は定めていない)。
4. なぜ、設定を変えたあとすぐに気づかなかったか。
   - 手順の一覧に、設定を変えたあとで効き方を確かめる段がなく、次のCIの実行(PR #108)まで、誤りが表に出なかったため。
5. 真因: メンテナーに設定の画面へ値を入れてもらう手順で、公式の文書で確かめた書式のまま貼れる値を示す段と、入れたあとで効き方を確かめる段がない。

## 真因

- 設定の画面に入れる値を依頼するときに、書式を確かめた値をそのまま示す段と、設定のあとで確かめる段がない。

## 対策

行ったこと:

- 手順の一覧の1.1に、許可するアクションの欄にそのまま貼る1行(コンマ区切り、`@*`付き)と、書き方の出典を書いた。設定を保存したあとで、CIを手動で実行して、ジョブが始まることを確かめる段を加えた。

案(規則の変更なので、メンテナーの承認が要る。2026-11-27に、メンテナーが(1)を行い、(2)を採った。(2)はAGENTS.mdの「進め方」のメンテナーへの依頼の箇条に、案のとおりに加えた):

1. 設定の直し(メンテナー): 欄の中身を、手順の一覧の1.1の1行に置き換える。
2. 規則: AGENTS.mdの「進め方」のメンテナーへの依頼の箇条に、次を加える。設定の画面に値を入れてもらうときは、公式の文書で書式(区切り、書き方)を確かめ、そのまま貼れる値を示す。設定が効いたことを確かめる手順(手動の実行など)も、あわせて示す。
3. 仕組み: 採らない。設定の画面の値は、リポジトリの外にあり、エージェントの道具では読めない(Actionsの権限の設定のAPIは、このセッションのプロキシで拒否された。記録0006の「確かめられなかったこと」)。

## 確かめ方

- メンテナーが設定を直したあとで、PR #108のCIのジョブが始まり、成功すること。
- このあとで設定の画面の値を依頼するときに、そのまま貼れる値と、効いたことを確かめる手順を示すこと。
