# 0021: 設定画面のGPUの初期化に、要件にある上限がないまま出した

- 日付: 2026-11-10
- ステータス: 対策の判断待ち(上限を加えるかどうかと、その時期を、メンテナーに確かめている)
- 関連: [計画0004](../plans/0004-v0.2.0-settings.md)のF-03・E-4・D-10、[ADR-0024](../adr/0024-settings-file-location-and-handling.md)のE-4、[0011](0011-log-written-against-requirement.md)

## 起きたこと

2026-11-10に、Phase 2の区切りの整合性の確認(`/consistency-check`)で、設定画面のGPUの初期化に上限がないことが分かった。要件(計画0004のF-03)は上限があることを前提にしているが、上限を設けないという決定の記録もない。v0.2.0は、この状態で公開した。

確かめた事実:

- 計画0004のF-03は、「異常終了(panic、初期化の上限による終了など)の前にも、オーナーを有効に戻す」としている。
- 計画0004のE-4は、設定画面のプロセスで、GPUが使えないとき(初期化の失敗、初期化が終わらないとき)の動作と、`/s`と`/p`の15秒の上限(計画0001のD-27)に当たる決まりを、作業8の前に決めるとしていた。
- ADR-0024のE-4が決めたのは、初期化に失敗して設定画面を開けないときに、メッセージボックスで設定ファイルのパスを示し、終了コード7で終わることだけである。初期化が終わらないときの扱いは決めていない。計画0004のD-10も、終了コード7だけを記録している。
- `/s`(`crates/app/src/saver.rs`)と`/p`(`crates/app/src/preview.rs`)は、`render::Watchdog`で15秒の上限を設け、終了コード6で終わる。設定画面(`crates/app/src/settings.rs`)には、上限がない。
- 設定画面は、オーナーを無効にする処理(`attach_owner`)を、eframeがアプリを作るときに行う。初期化が終わらない場合、オーナーは無効にならず、設定画面のプロセスだけが残ると考えられる(推測。eframeの内部で、アプリを作るのが描画の準備のあとであることは、ソースで確かめていない)。
- 実機やCIで、設定画面の初期化が終わらなかった例は、記録にない。

## なぜなぜ分析

| なぜ | 答え(確かめた事実) |
| --- | --- |
| なぜ上限がないまま出したか | E-4を決めたとき(ADR-0024)に、初期化の失敗だけを決め、初期化が終わらないときを決めなかったため。実装もそれに合わせた |
| なぜ決め漏れに気づかなかったか | E-4を「決めた」と記録したとき(計画0004の「あとで決めること」)に、E-4の項目に挙げた内容(失敗、終わらないとき、15秒の上限に当たる決まり、利用者に示すこと)と、決めた内容を突き合わせなかったため |
| なぜ突き合わせなかったか | 先送りした決定を決めたときに、項目の内容をすべて決めたかを確かめる手順がない。incident 0011の対策は、先送りした決定を計画に登録することで、決めたときの確かめ方は扱っていない |

## 真因

先送りした決定(E-x)を決めたときに、項目に挙げた内容をすべて決めたかを確かめなかった。そのため、要件(F-03)が前提にしている上限が、決めないまま、記録のないまま実装から抜けた。

## 対策

1. 現象への対応(メンテナーの判断を待っている。製品のコードの変更のため):
   - 案A(推奨): 設定画面にも`/s`・`/p`と同じ15秒の上限を設け、上限に達したら、オーナーを有効に戻し、メッセージボックスで開けなかったことを示して、終了コード7で終わる。Phase 3の最初の作業か、v0.2.1で行う。v0.2.0の既知の制限には、次の文書の変更で書く。
   - 案B: 上限を設けない。設定画面は利用者が操作して開くもので、終わらなければ利用者が閉じられる(タスクマネージャーなど)。計画0004の決定(D-xx)として記録し、F-03の「初期化の上限による終了など」を直す。
2. 手順(案。規則の変更のため、メンテナーの承認を待っている): 先送りした決定(E-x)を「決めた」と記録するときは、項目に挙げた内容ごとに、決めた内容と記録の場所を並べる。決めなかった内容は、改めて先送りして計画に登録する。AGENTS.mdの「進め方」の、incident 0011の規則の箇条に加える。

## 確かめ方

- 1の判断のあと、案Aなら、設定画面の初期化が15秒で終わらないときに終了することを、テストかスモークテストで確かめる。案Bなら、計画の決定と要件の記述が一致すること。
- 次に先送りした決定を決めるとき、項目ごとの対応の表が記録にあること。
