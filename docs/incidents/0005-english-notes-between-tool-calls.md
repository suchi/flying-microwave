# 0005: 対策のあとも、ツール呼び出しの合間に英語の文を表示した

- 日付: 2026-11-01
- ステータス: 対策中(対策のPRがマージされていない)
- 関連: [0001](0001-english-text-shown-to-maintainer.md)(同じ種類の異常の再発)

## 起きたこと

エージェントは、Spikesの手動実行を起動する前に「No runs in progress. Triggering on main (9385163).」と表示した。メンテナーは、意味が分からないと指摘した。0001で英語の表示の対策(規則とフック)をマージしたあとに起きた、再発である。

会話の記録を確かめると、このセッションで日本語を含まない文を17回表示していた。そのうち4回は、0001の対策をマージしたあとだった。どれも、ツールを呼び出す前に書いた短いひとことである(例: 「Fix M-1 in both hooks.」「Now edit gpu.rs.」)。また、エージェントは、考える過程もこのセッションのあいだ英語で書いていた。

確かめた一次情報:

- このセッションの会話の記録(assistantのメッセージのうち、ひらがな・カタカナ・漢字を含まないもの)。
- `.claude/hooks/require-japanese-reply.sh`の判定の対象。Stopの入力の`last_assistant_message`だけを見ている。
- 公式ドキュメント「Hooks reference」(2026-11-01に取得)。
  - `transcript_path`: 会話の記録は非同期に書かれるため、フックの時点で、そのターンの最新のメッセージを含まないことがある。
  - `MessageDisplay`: 表示されるassistantのメッセージのたびに動く。表示する文を置き換えられるが、表示を止めることはできない。置き換えた文はClaudeには見えない。

## なぜなぜ分析

| なぜ | 答え(確かめた事実) |
| --- | --- |
| なぜ英語の文が表示されたか | エージェントが、ツールを呼び出す前の短いひとことを英語で書いたため |
| なぜ英語で書いたか | 作業のメモのような短い文になると、英語で書くクセが出るため。規則(原則)は知っていたが、守れなかった |
| なぜ表示される前に止まらなかったか | 0001のフックが確かめるのは、ツールの説明文と、ターンの最後のメッセージだけだったため。ツール呼び出しの合間の文は、どこでも確かめていなかった |
| なぜ確かめる対象から漏れたか | 0001の対策を作るときに、メンテナーに文が表示される経路を洗い出さず、思いついた2つの経路だけを対象にしたため |

## 真因

仕組みの対策を作るときに、対象(メンテナーに表示される文の経路)を洗い出さなかったこと。規則の文言だけでは、エージェントのクセは直らない。

## 対策

1. 表示されるすべてのメッセージを確かめるフックを加えた。2026-11-01に、メンテナーの判断で廃止した(末尾の「再発の記録」を参照)。
   - flag-non-japanese-display.sh(MessageDisplay): メッセージ全体に日本語がなければ、表示の末尾に日本語の注意書きを付け、違反を記録する。
   - require-japanese-display.sh(PreToolUseのすべてのツールとStop): 違反の記録があれば、次のツールの呼び出しを拒否するか、ターンを続けさせる。その際、表示された文を示して、日本語での書き直しを求める。
2. 会話の記録(`transcript_path`)を読む方式は採らなかった。記録は非同期に書かれ、最新のメッセージを含まないことがあるため(公式ドキュメント)。
3. 表示そのものは、フックでは止められない。英語の文は一度は表示される。そのため、注意書きで違反だと分かるようにし、すぐに書き直させる。
4. 考える過程は、どのフックでも確かめられない(確かめた範囲)。規則に頼るしかなく、エージェントが日本語で書く。

## 確かめ方

- 2026-11-01の判断のあと: ターンの最後の報告とツールの説明文が日本語を含まないときは、フックが書き直しを求めること(`scripts/check_hooks.py`のサンプル入力で、CIが毎回確かめる)。ツール呼び出しの合間の文では、ツールの実行が止まらないこと。
- メンテナーへの指示・依頼・質問・説明・報告が、合間に書くものでも日本語で書かれていること。これは仕組みでは確かめられず、規則に頼る(上の対策4と同じ)。

## 再発の記録

2026-11-01に、ツール呼び出しの合間のひとことを英語で書いたことが3回あった(incidents 0008の作業中に1回、リリースのワークフローの作業中に2回)。3回とも、上の対策1のフックが検出し、次のツールの呼び出しを拒否して、書き直しを求めた。英語の文は、一度は表示された(対策3のとおり)。同じ種類の問題の再発のため、そのたびに作業を止めて、メンテナーに報告した。

| なぜ | 答え(確かめた事実) |
| --- | --- |
| なぜ英語の文が表示されたか | 作業の段取りを書いた短い文を、英語のまま書いたため |
| なぜ英語のまま書いたか | 考える過程を英語で進めていて、その流れのまま書いたため。2回目のあとに「考える過程も日本語で進める」としたが、実行できず、3回目が起きた |
| なぜ考える過程が英語になるか | 規則だけに頼っていて、考える過程を確かめる仕組みはないため(上の対策4) |

判断(メンテナー、2026-11-01): できるだけ日本語で書くという基本の姿勢は変えない。そのうえで、英語になる理由が分かっているので、考える過程とツール呼び出しの合間の短いメモが、やむを得ず英語になった場合は許容する。メンテナーへの指示・依頼・質問・説明・報告は、必ず日本語で書く。これに合わせて、次の対策を取る。

- AGENTS.mdの言語ルールの原則に、この例外を加えた。
- 表示の検査は、ターンの最後の報告(Stop。require-japanese-reply.sh)と、ツールの説明文(require-japanese-description.sh)だけにした。ツール呼び出しの合間の文を確かめていた2つのフック(上の対策1のflag-non-japanese-display.shとrequire-japanese-display.sh)は、メンテナーの承認を得て、登録を外して削除した([incidents 0009](0009-guard-hooks-never-ran.md)の対策と同じPR)。
