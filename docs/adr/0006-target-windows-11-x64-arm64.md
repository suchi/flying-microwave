# ADR-0006: 対象環境をWindows 11のx64とarm64にする

- ステータス: 採用
- 日付: 2026-10-31

## 背景

動作を確認し、配布物を用意する対象のWindowsのバージョンとCPUアーキテクチャを決める必要がある。対象を広げるほど検証の負担が増える一方、狭めると利用できない環境が増える。

Windows 11のx64とarm64、x64のみ、Windows 10も含める、の3案を比較した。実装計画の確認事項D-7として提示され、メンテナーが2026-10-31に決定した。

## 決定

対象環境をWindows 11のx64とarm64にする。

- ビルドターゲット: `x86_64-pc-windows-msvc`と`aarch64-pc-windows-msvc`([ADR-0001](0001-use-rust.md))。配布物はアーキテクチャごとのzipとする(案: `FlyingMicrowave-<version>-windows-x64.zip`、`FlyingMicrowave-<version>-windows-arm64.zip`)。
- Windows 10: 動作を保証しない。Windows 10は2025-10-14にサポートが終了している(Microsoftのライフサイクルのページに「Windows 10 will reach end of support on October 14, 2025」とある。[Microsoft Learn][MS-5])。
- arm64の検証: arm64の実機がなく手動テストができない場合は、リリースノートにarm64は未検証と明記する。
- 32ビット: サポートしない。
- 追加のランタイム: 必要としない(VC++ランタイムを静的リンクする。[ADR-0001](0001-use-rust.md))。

### 検討した選択肢と採用しなかった理由

- x64のみ: 検証は容易になる。しかしarm64機ではエミュレーションに頼ることになり、動作は要確認である。主要な環境を網羅するため採用しなかった。
- Windows 10も含める: 利用者が増える可能性がある。しかしサポートが終了したOSであり、保証できないため採用しなかった。

## 結果

- メリット:
  - 現行の主要な環境(Windows 11のx64・arm64)を網羅する。
  - サポート終了済みのOSへの対応を持たず、検証範囲を絞れる。
- デメリット・受け入れたトレードオフ:
  - arm64の実機がないと、arm64版は未検証のまま出荷される(リリースノートに明記する)。
  - Windows 10の利用者には動作を保証できない。
  - 配布物と手動テストの対象がx64とarm64の2つになり、CIの構成も2ターゲット分必要になる。
- 将来の見直し条件:
  - Windows 10での利用の要望が多く、動作確認の手段が得られたとき。
  - arm64の実機が得られず、未検証のままの出荷が続くとき(arm64の扱いを見直す)。
  - 32ビット環境のサポート要望が生じたとき。
