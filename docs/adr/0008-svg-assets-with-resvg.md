# ADR-0008: 素材をSVGで作り、resvgでラスタライズする

- ステータス: ~~採用~~ 非推奨 → [ADR-0023: svg-sprites-from-v0.2.0](0023-svg-sprites-from-v0.2.0.md) に置き換え
- 日付: 2026-10-31

> 非推奨理由: 本番の絵をv0.2.0の試作版に前倒しし、導入時期・依存の使い方・ドアの動かし方が決まったため(2026-11-03)。

## 背景

電子レンジと食べ物の素材を、どのデータ形式で作り、どう描画に取り込むかを決める必要がある。素材は自作または明確なライセンスのものに限る方針である([先行作品と知的財産上の配慮](../research/prior-art-and-ip.md)のIP-3)。4Kから小さなプレビュー枠までの解像度、モニタごとに異なるDPIでも鮮明に見える必要がある。

SVGとPNGのスプライトシートを比較した。実装計画の確認事項D-15として提示され、メンテナーが2026-10-31に決定した。素材の作り方は[ビジュアルデザイン方針](../design/visual-design.md#素材の作り方)に記録している。

## 決定

素材をSVGで作り、`resvg`でラスタライズして描画に使う。

- 導入時期: Phase 3から。`resvg` 0.49.0(Apache-2.0 OR MIT。2026-10-31に[crates.io][CIO-1]で確認)を使う。依存の追加はAGENTS.mdにより使用前の承認を要する。
- Phase 1・2: 仮素材(単純な図形)をwgpuで直接描く。SVGやresvgは使わない。
- 取り込み: 起動時に、表示サイズとDPIに合った解像度でラスタライズし、1枚のテクスチャアトラスにまとめる([アーキテクチャ](../design/architecture.md#描画))。
- アニメーション: ドアなどの部品を別素材に分け、描画時の変形(横方向の拡大縮小・回転)で動かす。フレームごとの絵を大量には用意しない。
- 記録: 素材ごとの作者・ライセンス・出典を`assets/sprites/README.md`に記録する。

### 検討した選択肢と採用しなかった理由

- PNGのスプライトシート: 単純で依存が増えない。しかし解像度ごとに素材を用意する必要があり、差分をテキストで確認できないため採用しなかった。

## 結果

- メリット:
  - 解像度に依存せず、どのモニタ・DPIでも鮮明に描ける。
  - テキストとして差分を確認でき、Inkscapeなどのオープンソースのツールで編集できる。
- デメリット・受け入れたトレードオフ:
  - 依存(resvg)が増える。
  - SVGの対応範囲に制約があり、使える表現がresvgの対応に左右される。
  - 起動時のラスタライズが起動時間の目標に影響しうる。Phase 3で計測する(未計測)。
- 将来の見直し条件:
  - 起動時のラスタライズが起動時間の目標を満たせないとき(ビルド時のラスタライズや事前生成を検討する)。
  - 必要な表現がresvgで描けないとき。
  - resvgの保守状況やライセンスに問題が生じたとき。
