# ADR-0004: 設定をTOMLファイルで保存する

- ステータス: 採用
- 日付: 2026-10-31

## 背景

設定画面で変更した値を保存し、`/s`・`/p`で読み込んで反映する必要がある。設定の保存形式は、データ形式に関わるためメンテナーの判断を要する事項である(AGENTS.md)。

TOMLファイルとWindowsレジストリを比較した。実装計画の確認事項D-4として提示され、メンテナーが2026-10-31に決定した。設定項目と検証規則は[設定項目仕様](../design/settings.md)、保存に関する設計は[アーキテクチャ](../design/architecture.md#設定の保存)に記録している。

## 決定

設定をTOMLファイルで保存する。

- 保存場所の解決: 利用者ごとの設定ディレクトリに保存する。OSごとの場所の解決には`directories`クレート(6.0.0、MIT OR Apache-2.0。2026-10-31に[crates.io][CIO-1]で確認)を候補とする。具体的な保存パスと解決の方法は、Phase 2の着手前に別のADRで決める。依存の追加はAGENTS.mdにより使用前の承認を要するため、本ADRは`directories`の追加の承認を意味しない。
- 検証規則: [設定項目仕様](../design/settings.md#検証規則)に従う。ファイルがない・大きすぎる(上限は64KiBを想定)・TOMLとして解析できない場合はすべて既定値で動作し、範囲外の数値は範囲内に丸め、型の違いはその項目だけ既定値にし、未知のキーは無視する。検証は`core::config`の純粋関数として実装し、規則の各行をテストケースにする。
- 書き込み: 一時ファイルに書いてから置き換える。`/s`が書きかけのファイルを読まないようにするため。
- 書き込みの禁止: `/s`・`/p`の実行中は設定ファイルに書き込まない(アーキテクチャのA-5)。書き込みは設定画面でのOK操作に限る。
- 読み込みの失敗: 読み込みに失敗しても既定値で動作し続ける(仕様調査のW-7、アーキテクチャのA-6)。
- TOMLの読み書きに使うcrateの候補: `serde` 1.0.229と`toml` 1.1.8(いずれもMIT OR Apache-2.0。[crates.io][CIO-1])。依存の追加はAGENTS.mdにより使用前の承認を要するため、本ADRは追加の承認を意味しない。

### 検討した選択肢と採用しなかった理由

- Windowsレジストリ: Windowsの慣例ではあるが、Windows専用でテストしにくい。将来のLinux版・macOS版で別の保存方式が必要になる。

## 結果

- メリット:
  - 人が読める形式で、OSをまたいで同じ形式を使え、テストしやすい。
  - Linux上でも設定の読み書きと検証を単体テストできる。
  - 一時ファイルを経由する置き換えにより、書きかけのファイルを`/s`が読む事故を避けられる。
- デメリット・受け入れたトレードオフ:
  - 保存場所をOSごとに解決する必要がある(候補は`directories`クレート)。
  - ユーザープロファイルや設定ファイルにアクセスできない状況では設定を反映できず、既定値で動作する。
  - 保存パスはまだ決まっておらず、別のADRが必要である。
- 将来の見直し条件:
  - 保存パスを決めるADRの作成時に、`directories`クレートの利用が適さないと分かったとき。
  - 設定項目が増えてスキーマ移行(`schema_version`)の管理が重くなったとき。
