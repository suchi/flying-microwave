# ADR-0019: `/s`のウィンドウを、winitの全画面の指定を使わずに作る

- ステータス: 採用
- 日付: 2026-11-01

## 背景

`/s`(スクリーンセーバーの本体)は、モニタごとにウィンドウを作り、各モニタを覆う([アーキテクチャ](../design/architecture.md))。winitには、全画面のウィンドウを作る指定(`with_fullscreen`)と、ウィンドウを前面に出す関数(`focus_window`)がある。

スパイクの2回目の実機での確認(2026-11-01)では、`with_fullscreen`で作った`/s`のウィンドウが、起動の直後に毎回終了した([スパイクの結果](../research/spike-results.md)の「2回目」の問題1)。winit 0.30.13のソース(`src/platform_impl/windows/window.rs`)で、原因を確かめた。

- `with_fullscreen`を付けて作ったウィンドウに対して、winitは作った直後に`force_window_active`を呼ぶ(1399〜1401行)。
- この関数は、ウィンドウを前面に出す許可を得るため、`SendInput`で拡張キーのAlt(右のAlt)の押下と解放を合成する(1537〜1574行)。
- `focus_window`も、ウィンドウが前面にないときは同じ関数を呼ぶ(1016〜1026行)。
- `SendInput`で合成した入力は、winitの`is_synthetic`では区別できない。終了の規則(合成でないキーの押下で終了する)では、この押下で終了してしまう。

## 決定

`/s`のウィンドウは、winitの`with_fullscreen`と`focus_window`を使わずに作る。

- 枠のない(`with_decorations(false)`)最前面(`WindowLevel::AlwaysOnTop`)のウィンドウを、モニタの位置と物理的な大きさで作る。
- 最初のウィンドウを、Win32の`SetForegroundWindow`で1回だけ前面に出す。キーボードの入力は、前面のウィンドウにしか届かないため。
- 拡大率の違うモニタへ動かしたときにwinitが大きさを変えないよう、`ScaleFactorChanged`でモニタの物理的な大きさを書き戻す(winit 0.30.13の`src/platform_impl/windows/event_loop.rs`の`WM_DPICHANGED`の処理。全画面でも最大化でもないウィンドウでは、論理的な大きさを保つように物理的な大きさを変える)。

スパイクの3回目と4回目の実機での確認で、この方式で起動直後に終了しなくなったことを確かめた。ログでは、2台のウィンドウのサーフェスの設定とフレームの描画に、エラーはなかった。主モニタでは、描画が目で見えることも確かめた。2台目のモニタの画面に描画が見えることは、まだ確かめていない(計画のPhase 1の段階1で確かめる)。同じ規則(キーの押下ですぐ終了)のスクリーンセーバーで、Win32で最初からモニタの大きさのウィンドウを作り、`SetForegroundWindow`を1回呼ぶものが、同じ環境で問題なく動いていることも参考にした。

### 検討した選択肢と採用しなかった理由

- `with_fullscreen`を使い、起動直後のAltの押下を無視する: 合成の押下と利用者の押下を区別できない。起動直後の一定時間だけキーを無視すると、終了の規則(キーの押下は猶予時間でもすぐ終了する)に反する。
- winitを使わず、Win32でウィンドウを作る: 確実だが、イベントループやwgpuとの連携を自分で書く量が増える。将来のLinux版・Mac版(AGENTS.mdのプロジェクト概要)でwinitを共有する利点も失う。

## 結果

- メリット: 起動直後に意図せず終了しない。winitのイベントループとwgpuの連携は、そのまま使える。
- デメリット・受け入れたトレードオフ: OSの「全画面」の状態にはならない。全画面に特有の最適化(表示の切り替えの省略など)は受けない。拡大率の違うモニタの組み合わせでの動作は、まだ実機で確かめていない(計画のPhase 1の段階1で確かめる)。
- 将来の見直し条件: winitが`with_fullscreen`で入力を合成しなくなったとき。拡大率の違うモニタの組み合わせで、モニタを覆えないと分かったとき。Standalone(単独アプリ)の全画面の切り替えは、作成後の`set_fullscreen`を使い、この関数を呼ばない(同じファイルで確かめた)ため、本ADRの対象外とする。
