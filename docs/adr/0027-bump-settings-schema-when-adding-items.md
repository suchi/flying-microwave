# ADR-0027: 設定ファイルに項目を加えた版では、schema_versionを上げる

- ステータス: 採用
- 日付: 2026-11-11

## 背景

設定ファイル(`config.toml`)には`schema_version`を書く([ADR-0024](0024-settings-file-location-and-handling.md)のE-3)。v0.2.0は、知っている項目だけを`schema_version = 1`で書き、未知のキーは保存で消える。自分より新しい`schema_version`のファイルを置き換える前だけ、設定画面の中で警告する。

v0.3.0では、設定項目を加える(`flight.style`、`flight.food_count`、`clock.enabled`、`clock.format`。[設定項目仕様](../design/settings.md))。`schema_version`を上げる基準は、これまでどこにも決めていなかった。上げなければ、v0.3.0で選んだ値を、v0.2.0の設定画面で保存したときに、警告なしに消える(既定値に戻る)。2026-11-11に、計画0005の作業7の前に、メンテナーが決めた。

## 決定

設定ファイルに項目を加えた版では、`schema_version`を1つ上げる。1つの版で複数の項目を加えるときは、まとめて1つ上げる。

- v0.3.0は`schema_version = 2`で書く。v0.3.0で加える項目は、すべて2に含める(最初に加える`flight.style`の作業で上げる。計画0005のD-15)。
- 読み込みは、これまでどおり古い版のファイルも読む。古いファイルにない項目は既定値にする。
- 項目を消したり、値の意味を変えたりする変更は、この決定の対象にしない(そのときに改めて決める)。

### 検討した選択肢と採用しなかった理由

- 上げない(1のまま): 読み書きの形式は変わらないが、古い版で保存したときに、新しい項目が警告なしに消える。
- 項目を1つ加えるたびに上げる: 開発中の版(プレリリース)ごとに番号が増え、意味が薄れる。正式な版の単位で足りる。

## 結果

- メリット:
  - 古い版の設定画面で保存する前に、利用者に警告が出る(ADR-0024の仕組みをそのまま使う)。
- デメリット・受け入れたトレードオフ:
  - v0.3.0のファイルを、v0.2.0の設定画面で保存するときは、警告を確かめるための操作が1回増える。
  - v0.3.0のプレリリースの間に保存したファイルも2になる。プレリリースの間に項目の扱いを変えても、番号は上げない。
- 将来の見直し条件:
  - 項目を消したり、値の意味を変えたりするとき(移行の仕組みが要るか決める)。
