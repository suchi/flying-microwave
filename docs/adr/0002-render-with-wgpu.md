# ADR-0002: 描画にwgpu(GPU)を採用する

- ステータス: 採用
- 日付: 2026-10-31

## 背景

スクリーンセーバーはPCの放置中に長時間動くため、CPU負荷と消費電力を抑えることを優先する。4Kや複数モニタでも負荷が低く、将来の演出(拡大縮小、回転、半透明、パーティクル、背景のグラデーション)に余裕がある描画方式が必要である。

GPU描画(wgpu)とCPU描画(softbufferとtiny-skia)を比較した。比較の詳細は[言語・エコシステムの比較検討](../research/tech-stack.md#描画方式の比較)に記録している。実装計画の確認事項D-2として提示され、メンテナーが2026-10-31に決定した。言語は[ADR-0001](0001-use-rust.md)でRustに決まっている。

## 決定

GPU描画にwgpu(30系。2026-10-31時点で確認した最新安定版は30.0.1。[crates.io][CIO-1])を採用する。

- DX12シェーダーコンパイラとバックエンドの明示: DX12のシェーダーコンパイラを`Fxc`に明示し、使うバックエンドも明示する(アーキテクチャのSEC-2)。wgpu-hal 30.0.1は`d3d12.dll`・`dxgi.dll`・`dxcompiler.dll`をパスなしの名前で動的に読み込み、DX12のシェーダーコンパイラの既定値(`Dx12Compiler::Auto`)は`dxcompiler.dll`の読み込みを先に試す(ソースで確認。[wgpu-hal 30.0.1][WGPU-1])。`.scr`は利用者が展開した任意のフォルダに置かれて自動実行されうるため、同じフォルダのDLLを読み込まないための対策の1つとして行う([アーキテクチャのセキュリティ](../design/architecture.md#セキュリティ))。DLL検索パスの制限(SEC-1)と併用する。具体的なバックエンド構成と、SEC-1のAPI・リンカ設定の詳細は、実装時に公式ドキュメントを確認して決める。
- アダプタの選択: 省電力(low-power)のGPUアダプタを優先して選ぶ。ハイブリッドGPU環境で外部GPUを起こさないため。
- GPUが使えない環境: DX12のWARP(ソフトウェア描画)へのフォールバックの可否は、スパイクS6の結果で決める。
- 初期化に失敗した場合: `/s`でGPUの初期化に失敗しても、黒い全画面を維持したまま入力を待つ(仕様調査のW-9)。すぐに終了すると、画面を隠す目的を果たせず、再開時にロックする設定の環境では直後にロック画面になるため。`/p`では静かに終了する。
- テスト: 描画以外のロジックは`core`に分離して単体テストする。描画結果の画像比較は当面行わず、必要になればwgpuのオフスクリーン描画で行う。

### 検討した選択肢と採用しなかった理由

- CPU描画(softbuffer 0.4.8 + tiny-skia 0.12.0): 実装が単純で、描画結果を画素比較でテストしやすい。しかし4K(3840x2160)の32bitフレームは約33MBで、60fpsで全面を描き直すと毎秒約2GBのメモリ書き込みになる(概算・未計測)。省電力性に不利なため採用しなかった。

## 結果

- メリット:
  - 4K・複数モニタでもCPU負荷が低く、拡大縮小・回転・半透明がほぼ無償で使える。
  - 将来の演出(パーティクル、背景のグラデーション)に余裕がある。
  - ADR-0001で採用したwinit・eframeとwgpuを共有できる。
- デメリット・受け入れたトレードオフ:
  - シェーダ(WGSL)とスプライトバッチの実装が必要で、CPU描画より実装量が多い。
  - GPUが使えない環境(仮想マシン、古いドライバ)への対応が必要になる。
  - DLLの読み込みに関する対策(SEC-1・SEC-2)が必要になる。
  - 描画結果の自動テストは当面行わない。
- 将来の見直し条件:
  - スパイクS6で、GPUのない環境での挙動が許容できないと分かったとき(WARPが使えず、黒い画面のまま止まる環境が多い場合など)。
  - Phase 1の計測で、CPU負荷の目標(4Kモニタ1台・60fpsで論理1コアの10%以下)をGPU描画でも満たせないとき。
  - wgpuのDLL読み込みに関する対策を実装できないとき。
