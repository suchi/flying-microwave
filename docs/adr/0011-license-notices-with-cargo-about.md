# ADR-0011: 依存crateのライセンス表記をcargo-aboutで生成する

- ステータス: 採用
- 日付: 2026-10-31

## 背景

配布物には依存crateのライセンス表記を同梱する必要がある(実装計画の非機能要件N-12)。同梱が漏れるとライセンス違反になりうる(リスクR-11)。依存が増えるほど手作業での管理は漏れやすくなる。

自動生成ツールのcargo-aboutと、手作業での維持を比較した。実装計画の確認事項D-17として提示され、メンテナーが2026-10-31に決定した。

## 決定

依存crateのライセンス表記を、cargo-about(0.9.3、MIT OR Apache-2.0。2026-10-31に[crates.io][CIO-1]で確認)のテンプレートから生成する。

- 導入時期: Phase 1。リリースワークフローに生成を組み込む。
- 同梱先: リリースのzipに同梱し、設定画面のAboutタブにも表示する。Aboutタブは設定画面と同時にPhase 2で導入する([設定項目仕様](../design/settings.md#設定画面))。
- crateのメタデータ外のライセンス: フォントや素材(SVGなど)のように、crateのメタデータに現れないライセンスは、手作業で確認する。フォントの方針は[ADR-0003](0003-settings-ui-with-eframe.md)、素材の記録は[ADR-0008](0008-svg-assets-with-resvg.md)に従う。
- 本プロジェクト自身のライセンスは[ADR-0005](0005-license-mit.md)で決めている。

### 検討した選択肢と採用しなかった理由

- 手作業での維持: ツールが不要である。しかし依存の更新のたびに更新が必要で、漏れやすいため採用しなかった。

## 結果

- メリット:
  - 依存crateのライセンス表記をテンプレートから自動で生成でき、依存の更新に追従しやすい。
  - リリースワークフローに組み込めば、同梱漏れを防げる。
- デメリット・受け入れたトレードオフ:
  - cargo-aboutが扱うのはcrateのメタデータだけで、フォントや素材のライセンスは別途確認が必要である。
  - ツールのバージョン管理と、テンプレートの保守が必要になる。
- 将来の見直し条件:
  - cargo-aboutの保守が止まる、または生成結果が不正確と分かったとき。
  - crateのメタデータ外のライセンスの確認が漏れやすいと分かったとき(確認の自動化を検討する)。

[CIO-1]: https://crates.io/
