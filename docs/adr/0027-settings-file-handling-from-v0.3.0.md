# ADR-0027: 設定ファイルの場所と扱いを決める(v0.3.0から。項目を加えた版ではschema_versionを上げる)

- ステータス: 採用
- 日付: 2026-11-11
- 置き換え: [ADR-0024: settings-file-location-and-handling](0024-settings-file-location-and-handling.md) を非推奨とし、本ADRが最新の決定となる

## 背景

[ADR-0024](0024-settings-file-location-and-handling.md)は、設定ファイルの場所と扱い(テストでの場所の切り替え、書き込みの形式、設定画面を開けないとき、フォントと読み上げ、場所を取得できないとき、読み込みの時機)を決めた。書き込みの形式(E-3)では、知っている項目を`schema_version = 1`で書き、未知のキーは保存で消える。新しい`schema_version`のファイルや、読めなかったファイルを置き換える前は、設定画面の中で警告する。

v0.3.0では、設定項目を加える(`flight.style`、`flight.food_count`、`clock.enabled`、`clock.format`。[設定項目仕様](../design/settings.md))。`schema_version`を上げる基準は、これまで決めていなかった。上げなければ、v0.3.0で選んだ値を、v0.2.0の設定画面で保存したときに、警告なしに消える(既定値に戻る)。2026-11-11に、計画0005の作業7の前に、メンテナーが、項目を加えた版では`schema_version`を上げると決めた([計画0005](../plans/0005-v0.3.0-visuals-and-clock.md)のD-15)。これはADR-0024のE-3の決定(1で書く)を変えるため、ADRの運用ルールに従い、ADR-0024の決定をすべて引き継いだうえで、E-3を改める本ADRで置き換える。E-3のほかの決定は、ADR-0024から変えていない。

## 決定

- 場所: `%APPDATA%\FlyingMicrowave\config.toml`(利用者ごと・ローミングする)。`SHGetKnownFolderPath(FOLDERID_RoamingAppData)`で求める(既存の`windows-sys`。`directories`クレートは使わない)。Linux・macOSの場所は、その版を作るときに決める。
- テストでの場所の切り替え(E-1): 環境変数`FLYING_MICROWAVE_CONFIG_DIR`に、ドライブ文字で始まる絶対パス(`C:\...`か`\\?\C:\...`)のフォルダを指定すると、その下の`config.toml`を使う。空の値は指定なしとする。それ以外の値(相対パス、UNCのパス、デバイスのパス)はエラーにし、本当の設定ファイルを使わない(テストやローカルでの実行が、利用者のファイルを読んだり置き換えたりしないため)。UNCのパスを受け付けないのは、ネットワークを使わないため(SEC-5)である。ネットワークドライブを割り当てたドライブ文字は区別できないが、テスト用の変数なので受け入れる。
- 書き込みの形式(E-3): 一時ファイル(`config.toml.<pid>.tmp`)に書いてから置き換える。知っている項目を、その版の`schema_version`で書き、未知のキーとコメントは残らない。設定ファイルに項目を加えた版では、`schema_version`を1つ上げる。1つの版で複数の項目を加えるときは、まとめて1つ上げる。v0.2.0は1で書き、v0.3.0は2で書く(v0.3.0で加える`flight.style`、`flight.food_count`、`clock.enabled`、`clock.format`は、すべて2に含める。最初に加える`flight.style`の作業で上げる。[計画0005](../plans/0005-v0.3.0-visuals-and-clock.md)のD-15)。古い版のファイルも読み、ないキーは既定値にする。項目を消したり、値の意味を変えたりする変更は、この決まりの対象にしない(そのときに改めて決める)。新しい`schema_version`のファイルや、読めなかったファイル(TOMLでない、大きすぎる、読み込みの失敗)を置き換える前は、設定画面の中に警告を示し、表示がReplaceに変わったボタンで確かめてから書く。ダブルクリックで読まずに保存しないよう、警告を出してから0.7秒は確認として数えない。`schema_version`がない・整数でない・0以下のときは1として読む。
- 設定画面を開けないとき(E-4): GPUの初期化の失敗などで設定画面を開けないときは、メッセージボックスで、開けなかったことと設定ファイルのパスを示し、終了コード7で終わる。
- フォントと読み上げ(E-5): Windowsのフォントのフォルダ(`SHGetKnownFolderPath(FOLDERID_Fonts)`)の`segoeui.ttf`を読み、なければ`arial.ttf`を読む。eframeの機能は`wgpu_no_default_features`だけにし、スクリーンリーダーへの対応(`accesskit`)、URLを開くこと、クリップボードは無効のままにする。スクリーンリーダーへの対応は、v1.0.0の前に改めて判断する([計画0001](../plans/0001-initial-implementation-plan.md)のPhase 6に登録した)。
- 場所を取得できないとき(E-6): 読み込みでは既定値で動き、保存では設定画面の中にエラーを示す。
- 読み込みの時機: `/s`は、設定を別のスレッドで読み、すべてのモニタを黒で覆ったあとで最大0.5秒待つ。間に合わないか失敗したときは、その回は既定値で動く(計画0004のD-9)。`/p`と設定画面は、起動時に読んでから始める。

### 検討した選択肢と採用しなかった理由

ADR-0024で検討した選択肢(`directories`クレート、`%LOCALAPPDATA%`、`toml_edit`で未知のキーとコメントを残す、受け付けない環境変数の値を無視する)は、ADR-0024のとおりである。`schema_version`の上げ方について、次の案を採らなかった。

- 上げない(1のまま): 読み書きの形式は変わらないが、古い版で保存したときに、新しい項目が警告なしに消える。
- 項目を1つ加えるたびに上げる: 開発中の版(プレリリース)ごとに番号が増え、意味が薄れる。正式な版の単位で足りる。

## 結果

- メリット:
  - 依存を増やさずに、利用者ごとの場所を求められる。
  - テストが利用者のファイルに触れない。
  - 利用者のファイルを、確認なしに置き換えない。項目を加えた版のファイルを古い版で保存する前にも、警告が出る。
  - 設定の読み込みが遅くても、画面を覆うまでの時間を守れる。
- デメリット・受け入れたトレードオフ:
  - 新しい版で書かれた設定ファイルを古い版で保存すると、知らない項目は消える(警告はする)。
  - v0.3.0のファイルを、v0.2.0の設定画面で保存するときは、警告を確かめるための操作が1回増える。
  - 同じ`schema_version`の間で項目を加えたプレリリースどうしでは、警告が出ない。たとえば、`v0.3.0-alpha.3`で加える項目の値は、`alpha.3`で保存したファイルを`alpha.2`の設定画面で保存すると、警告なしに消える(どちらも2のため)。プレリリースを行き来するのは主に開発参加者なので、受け入れる。
  - 設定画面は、スクリーンリーダーで読めない。
  - `/s`で設定の読み込みが0.5秒を超えると、その回は既定値で動く。
- 将来の見直し条件:
  - Linux版・macOS版を作るとき(場所の決め方)。
  - 設定項目が増え、版をまたいで設定を保つ必要が出たとき(未知のキーの扱い)。
  - 項目を消したり、値の意味を変えたりするとき(移行の仕組みが要るか決める)。
  - v1.0.0の前の、スクリーンリーダーへの対応の判断。
