# ADR-0007: 敵対的レビューを別コンテキストのエージェントで行い、GitHub Copilotのレビューは使わない

- ステータス: 採用
- 日付: 2026-10-31

## 背景

AGENTS.mdのプロジェクト概要は「敵対的レビューを行い、GitHub Copilotは利用しない」と定めている。一方、同じファイルの「PR・レビュー・マージ」節、`.claude/commands/babysit-pr.md`、`.github/copilot-instructions.md`、`.github/copilot-code-review.yml`はCopilotによるレビューを前提にしており、不整合がある(実装計画の不整合I-1)。

実装計画の確認事項D-8として、レビューの方法とCopilot関連の記述・設定の扱いを提示し、メンテナーが2026-10-31に決定した。計画自体も、別コンテキストのエージェントによる敵対的レビューを実施し、[敵対的レビュー記録](../reviews/0001-plan-adversarial-review.md)に残している。

## 決定

### レビューの方法

PRごとに、作成者とは別のコンテキストを持つレビュー用エージェント(Claude Codeのサブエージェント、または`/code-review`スキル)に、差分と要件だけを渡して欠陥を探させる。作成者の結論は渡さない。結論に引きずられないようにするため。ただし再レビューでは、対応の妥当性を確かめさせるため、例外として前回の指摘と対応の一覧も渡す。

- 指摘の扱い: 指摘は検証すべき主張として扱い、一次情報(公式ドキュメント、ソース、レジストリなど)で確かめてから対応する。
- 対応: 各指摘は、修正するか、対応しない理由を答えるかのいずれかで返す。新規の指摘がなくなるまで、再レビューを繰り返す。
- 二重のレビュー(任意): 重要な変更(アーキテクチャ、セキュリティ、リリース関連)では、別系統のモデル(例: OpenAI Codex)による2回目のレビューを任意で行う。同系統のモデルは盲点を共有しうるためである。
- マージの条件: CIの全ジョブがグリーン、レビュー完了、メンテナーの承認の3つがそろってからマージする。
- 記録: 指摘と対応はPR上に残す。計画・設計のレビューは`docs/reviews/`に記録する。

### Copilotのレビューの扱い

本リポジトリではGitHub Copilotのレビューを使わない。ただしCopilotを使う場合の手順は代替手段として[docs/development/review-process.md](../development/review-process.md)に残す。どちらの方法でも、「指摘への対応、スレッドへの返信、再レビュー、新規指摘ゼロまで繰り返す」という同じループに従う。

この決定に合わせて、AGENTS.mdの「PR・レビュー・マージ」節と`.claude/commands/babysit-pr.md`・`.claude/commands/merge-pr.md`を更新した。Copilot向けの設定ファイル(Copilot全般向けの薄いポインタでレビューを日本語で書く指示を含む`.github/copilot-instructions.md`と、レビューの言語設定の`.github/copilot-code-review.yml`)は、Copilotを使う場合に備えて残す。Copilotを使わない間は影響しない。

### 検討した選択肢と採用しなかった理由

- GitHub Copilotによるレビュー: AGENTS.mdのプロジェクト概要がCopilotを利用しないと定めているため採用しない。
- 作成者自身による確認だけ: 作成者の結論に引きずられ、欠陥を見落としやすいため採用しない。
- 別系統のモデルを常に併用: 視点は増えるが、手間と費用が増える。重要な変更に限って任意とした。

## 結果

- メリット:
  - 作成者の結論を共有しない別コンテキストにより、欠陥を探す視点が独立する。
  - 指摘を検証してから対応するため、誤った指摘による不要な変更を避けられる。
  - Copilotの手順を代替として残すため、方針を変えても同じループで運用できる。
- デメリット・受け入れたトレードオフ:
  - 同系統のモデルは盲点を共有しうる。任意の2回目のレビューで補うが、常には行わない。
  - 指摘の検証に手間がかかる。
  - 使わないCopilot用の設定ファイルをリポジトリに残す。
- 将来の見直し条件:
  - レビューで見落としによる欠陥が繰り返し出荷されたとき(別系統のモデルの併用を常時にするなどを検討する)。
  - レビューの費用や時間が開発の妨げになるとき。
  - Copilotのレビューを使う方針に変えるとき。
