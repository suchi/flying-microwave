# 0004: v0.2.0 設定画面(Phase 2)

- ステータス: 合意済み(2026-11-03)
- 日付: 2026-11-03
- 関連: [計画0001](0001-initial-implementation-plan.md)のPhase 2、F-04・F-06・F-07、D-24・D-28、[設定項目仕様](../design/settings.md)、[アーキテクチャ](../design/architecture.md)、[ADR-0003](../adr/0003-settings-ui-with-eframe.md)、[ADR-0004](../adr/0004-store-settings-as-toml.md)、Issue #28・#29・#3

## 目的

設定画面から主要なパラメーターを変えられるようにし、`/s`と`/p`に反映する(F-06)。計画0001のPhase 2の作業を、実装できる単位に分け、決めることを並べる。

着手の条件: v0.1.1(計画0003)が完了していること(計画0001のD-24)。本計画は、それより前に合意し、v0.1.1の完了後すぐに始められるようにした。

## 範囲

- 対象: [設定項目仕様](../design/settings.md)のv0.2.0の6項目(`flight.count`、`flight.speed`、`flight.scale`、`display.max_fps`、`display.monitors`、`input.exit_sensitivity`)、設定ファイルの読み書き、設定画面(Flight・Display・Aboutのタブ、OK・Cancel・Defaults)、`/s`と`/p`への反映、`/s`の実行中のモニタの変更への対応(F-07)。
- 対象外: v0.3.0以降の項目(食べ物、時計、背景、隠し要素)、Extrasのタブ、単独アプリとしての実行(F-12)、本番の絵(Phase 3)。

## 要件

| ID | 要件 |
| --- | --- |
| F-01 | 設定ファイルを読み、[設定項目仕様の検証規則](../design/settings.md#検証規則)のとおりに値を決める。規則の各行をテストにする(`core::config`の純粋関数) |
| F-02 | 設定画面のOKで、一時ファイルに書いてから置き換える。`/s`と`/p`は書き込まない(ADR-0004) |
| F-03 | `/c`・`/c:<HWND>`・引数なし(`.scr`のとき)・認識できない引数で、設定画面を表示する。`/c:<HWND>`では、そのウィンドウをオーナーにしてモーダル相当にし、閉じたらオーナーを有効に戻して前面に戻す(計画0001のF-04、スパイクS2) |
| F-04 | 設定画面は、Flight・Display・Aboutのタブと、OK・Cancel・Defaultsのボタンを持つ。UIラベルは英語(設定項目仕様のUIラベル)。保存に失敗したら、設定画面の中にエラーを表示する |
| F-05 | Aboutのタブに、版、ライセンス、依存ライブラリのライセンス表記、着想元についての説明(IP-1の範囲)、プロジェクトのURLを表示する。隠し要素には触れない |
| F-06 | `/s`と`/p`は、起動時に設定を読み、6項目を反映する(`display.monitors = "primary"`では、ほかのモニタは黒で覆う) |
| F-07 | `/s`の実行中にモニタが追加・変更されても、すべてのモニタを覆う(計画0001のF-07) |
| F-08 | 設定ファイルの`schema_version`が新しいときは、読める項目だけを使い、OKで書き込む前に、利用者に確認する |
| N-01 | 表示の拡大率(100%、150%など)を変えても、設定画面の配置が崩れない(Issue #29) |
| N-02 | 設定画面の見た目は、配置と余白を整えたものにし、案をメンテナーが確かめてから実装する(計画0001のPhase 2の見た目の要件、Issue #29) |
| N-03 | 新しい依存は、下の決定(D-2・D-3)で承認したものだけにする。公開から7日以上の版を使う(AGENTS.md) |

## 決定

2026-11-03に、メンテナーが次のとおり決めた。

| ID | 内容 |
| --- | --- |
| D-1 | 設定ファイルの場所は、`%APPDATA%\FlyingMicrowave\config.toml`(利用者ごと・ローミングする)とし、Windows APIの`SHGetKnownFolderPath`(`FOLDERID_RoamingAppData`。既存の`windows-sys`)で求める。新しいADRに記録する(作業2)。ADR-0004で候補とした`directories`クレートは使わない。依存が増え、`windows-sys`の別の版を持ち込むおそれがあるため(未確認)。`%LOCALAPPDATA%`は、PCをまたいで同じ設定を使えないため採らない。Linux・macOSの場所は、その版を作るときに決める |
| D-2 | eframe `=0.37.0`を加える(ADR-0003の追加の承認)。機能は、スパイク(settings-spike)と同じく`wgpu_no_default_features`だけにし、既定のフォントは使わず、システムのフォントを読み込む。スパイクで、製品と同じwgpu 30.0.1・winit 0.30.13と組み合わせて実機で動いた。加える時点で、公開からの日数(AGENTS.md)と、GUIのcrateの重複(計画0001のR-05)を確かめる |
| D-3 | `serde`と`toml`を、実行時の依存に加える(ADR-0004の追加の承認)。どちらも、embed-resourceのビルド時の依存として、すでに`Cargo.lock`にある(serde 1.0.229、toml 1.1.8)。加える時点で、新しいcrateが増えないかを`cargo tree`で確かめる |
| D-4 | 設定画面の見た目の参考にする別のリポジトリ(計画0001のD-24)は、メンテナーが、見た目の案を作る前(作業6の前)に示す |
| D-5 | 見た目の案(N-02)は、まずHTMLとSVGの静的な案で示し、メンテナーが確かめて合意してから、eframeで作る。案は、eguiの部品で作れる配置に限る。エージェントはWindowsで画面を確かめられないため、実機での確認の回数を減らす。最初からeframeで作る案は、直すたびに実機での確認が要るため採らない |

## 作業

1. 用語の点検(Issue #28)。Phase 2の最初に行う(計画0001のD-24)。文書だけの変更で、軽いレビューを1回行う。
2. 設定ファイルの場所のADR(D-1)。
3. `core::config`: 6項目のモデル、既定値、検証規則(TDD)。
4. `storage`: 場所の解決、サイズの上限(64KiB)、壊れたファイルの扱い、一時ファイルを使った置き換え(TDD。Windowsに依存しない部分はLinuxでもテストする)。
5. `/s`と`/p`への反映(F-06)。スモークテストで、設定ファイルがない場合と壊れている場合も起動と終了ができることを確かめる(計画0003のスモークテストに加える)。
6. 見た目の案(D-5)と、メンテナーの確認。参考のリポジトリ(D-4)は、この作業の前に、読み取りだけの権限でセッションに加え、画面の構成と配置だけを参考にする。
7. 設定画面(eframe): タブ、ボタン、オーナーに対するモーダル化と前面への復帰(F-03)、保存の失敗の表示、`schema_version`の確認(F-08)。
8. モニタの変更への対応(F-07)。実装の前に、Windowsが送る通知(`WM_DISPLAYCHANGE`など)と、winit 0.30.13での受け取り方を一次情報で確かめ、方式を決める。
9. 利用者向けREADMEに、設定の使い方と設定ファイルの場所を書く。CHANGELOG。
10. 公開の前の点検(Issue #3)と、公開の時期の判断(計画0001のD-24)。
11. `spikes/`とスパイクのワークフローの削除(計画0001のD-28)。設定画面ができたあと、最後に行う。
12. v0.2.0のプレリリースと実機での確認、正式なリリース。

PRは、作業ごとか、まとまった単位で作る(作業3と4、作業7と9など)。

## 完了条件

- 計画0001の共通のリリース条件(7.1)を満たしている。
- 設定の保存と反映、壊れた設定ファイルでもクラッシュしないことを、テストと実機で確かめている。
- スパイクS2の残り(オーナーのウィンドウを前面に戻すこと)を製品で確かめ、記録している(計画0001のD-20)。
- 設定画面の見た目を、拡大率100%と150%で実機で確かめている(N-01)。
- `spikes/`とスパイクのワークフローを削除している(計画0001のD-28)。

## リスク

- eframeの設定画面と、`/c:<HWND>`のオーナーとの関係: スパイクでは、オーナーを無効にできたが、`SetForegroundWindow(owner)`が失敗した(スパイクの結果のS2)。前面に戻せない場合の扱いを、作業7で決める。
- 設定画面の見た目を、エージェントは画面で確かめられない。見た目の案(D-5)で合意してから作り、実機での確認で直す。
- モニタの変更の通知を、winitがどう扱うかは確かめていない(作業8)。
