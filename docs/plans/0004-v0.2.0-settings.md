# 0004: v0.2.0 設定画面(Phase 2)

- ステータス: 合意済み(2026-11-03)
- 日付: 2026-11-03
- 関連: [計画0001](0001-initial-implementation-plan.md)のPhase 2、計画0001のF-04・F-06・F-07、D-20・D-24・D-27・D-28、[設定項目仕様](../design/settings.md)、[アーキテクチャ](../design/architecture.md)、[ADR-0003](../adr/0003-settings-ui-with-eframe.md)、[ADR-0004](../adr/0004-store-settings-as-toml.md)、[ADR-0011](../adr/0011-license-notices-with-cargo-about.md)、Issue #28・#29・#3

本計画の要件のID(F-xx、N-xx)は本計画のものである。計画0001の要件を指すときは、「計画0001の」を付ける。

## 目的

設定画面から主要なパラメーターを変えられるようにし、`/s`と`/p`に反映する(計画0001のF-06)。計画0001のPhase 2の作業を、実装できる単位に分け、決めることを並べる。

着手の条件: v0.1.1(計画0003)をリリースしていること(計画0001のD-24)。v0.1.1の実機での確認の記録と商標の確認の残り(Issue #47)は、本計画の完了条件で扱う。本計画は、それより前に合意し、v0.1.1のリリースのあとすぐに始められるようにした。

## 範囲

- 対象: [設定項目仕様](../design/settings.md)のv0.2.0の6項目(`flight.count`、`flight.speed`、`flight.scale`、`display.max_fps`、`display.monitors`、`input.exit_sensitivity`)、設定ファイルの読み書き、設定画面(Flight・Display・Aboutのタブ、OK・Cancel・Defaults)、`/s`と`/p`への反映、`/s`の実行中のモニタの変更への対応(計画0001のF-07)。
- 対象外: v0.3.0以降の項目(食べ物、時計、背景、隠し要素)、Extrasのタブ、単独アプリとしての実行(計画0001のF-12)、本番の絵(Phase 3)。

## 要件

| ID | 要件 |
| --- | --- |
| F-01 | 設定ファイルを読み、[設定項目仕様の検証規則](../design/settings.md#検証規則)のとおりに値を決める。規則の各行をテストにする(`core::config`の純粋関数) |
| F-02 | 設定画面のOKで、一時ファイルに書いてから置き換える。`/s`と`/p`は書き込まない(ADR-0004) |
| F-03 | [アーキテクチャの起動モードの判定](../design/architecture.md#起動モードの判定)でSettingsになるすべての入力(引数なしの`.scr`、`--settings`、`/c`、`/c:<HWND>`・`/c <HWND>`、HWNDのない`/p`、認識できない引数など)で、設定画面を表示する。`/c`では前面のウィンドウを、`/c:<HWND>`ではそのウィンドウを、有効なウィンドウか検証してから(SEC-3)オーナーにし、モーダル相当にする。閉じたらオーナーを有効に戻し、前面に戻す。異常終了(panic、初期化の上限による終了など)の前にも、オーナーを有効に戻す(計画0001のF-04、スパイクS2) |
| F-04 | 設定画面は、Flight・Display・Aboutのタブと、OK・Cancel・Defaultsのボタンを持つ。UIラベルは英語(設定項目仕様のUIラベル)。保存に失敗したら、設定画面の中にエラーを表示する |
| F-05 | Aboutのタブに、版、ライセンス、依存ライブラリのライセンス表記(ADR-0011)、着想元についての説明(IP-1の範囲)、プロジェクトのURLを表示する。隠し要素には触れない。ライセンス表記の示し方はE-2で決める |
| F-06 | `/s`と`/p`は、起動時に設定を読む。`/s`は6項目を反映する(`display.monitors = "primary"`では、ほかのモニタは黒で覆う)。`/p`は、`flight.*`と`display.max_fps`を反映する(`display.monitors`と`input.exit_sensitivity`は、1つの子ウィンドウで入力を無視する`/p`には当てはまらない)。設定の読み込みで、全画面を黒で覆うまでの時間(計画0001のN-01)を遅らせない |
| F-07 | `/s`の実行中にモニタが追加・変更されても、すべてのモニタを覆う(計画0001のF-07) |
| F-08 | 設定ファイルの`schema_version`が新しいときは、読める項目だけを使い、OKで書き込む前に、利用者に確認する。書き込みの形式はE-3で決める |
| F-09 | 設定画面のプロセスにも、SEC-1(DLLの検索パスの制限)とSEC-2(DX12とFxcの明示)を適用する。GPUが使えないときの動作はE-4で決める |
| N-01 | 表示の拡大率(100%、150%など)を変えても、設定画面の配置が崩れない(Issue #29) |
| N-02 | 設定画面の見た目は、配置と余白を整えたものにし、案をメンテナーが確かめてから実装する(計画0001のPhase 2の見た目の要件、Issue #29) |
| N-03 | 新しい依存は、下の決定(D-2・D-3)で承認したものだけにする。公開から7日以上の版を使う(AGENTS.md) |

## 決定

2026-11-03に、メンテナーが次のとおり決めた。

| ID | 内容 |
| --- | --- |
| D-1 | 設定ファイルの場所は、`%APPDATA%\FlyingMicrowave\config.toml`(利用者ごと・ローミングする)とし、Windows APIの`SHGetKnownFolderPath`(`FOLDERID_RoamingAppData`。既存の`windows-sys` 0.61.2の`Win32_UI_Shell`にある)で求める。新しいADRに記録する(作業2)。ADR-0004で候補とした`directories`クレートは使わない。`directories` 6.0.0は、`dirs-sys`と`option-ext`を合わせて3つのcrateを加え、Windowsでは同じ`SHGetKnownFolderPath`を呼ぶだけなので、自前で書ける(crates.ioの索引で確かめた)。`%LOCALAPPDATA%`は、PCをまたいで同じ設定を使えないため採らない。Linux・macOSの場所は、その版を作るときに決める |
| D-2 | eframe `=0.37.0`を加える(ADR-0003の追加の承認)。機能は、スパイク(settings-spike)と同じく`wgpu_no_default_features`だけにし、既定のフォントは使わず、システムのフォントを読み込む。スパイクで、製品と同じwgpu 30.0.1・winit 0.30.13と組み合わせて実機で動いた(`spikes/settings-spike/Cargo.lock`で確かめた)。加える時点で、公開からの日数(AGENTS.md)と、GUIのcrateの重複(計画0001のR-05、`ci.yml`の検査)を確かめる。この機能の組み合わせでは、スクリーンリーダーへの対応(`accesskit`)、URLを開くこと(`links`)、クリップボード(`clipboard`)が無効になる。この扱いと、フォントの選び方はE-5で決める |
| D-3 | `serde`と`toml`を、実行時の依存に加える(ADR-0004の追加の承認)。`toml` 1.1.8は、embed-resourceのビルド時の依存として`Cargo.lock`にある。`serde` 1.0.229も`Cargo.lock`にあるが、いまの依存のグラフでは使われていない(`cargo tree -i serde`で確かめた)。加えると、`serde`・`serde_derive`・`toml`とその依存が実行時の依存になり、ライセンス表記とSBOMの対象が増える(`about.toml`はビルド時の依存を数えないため)。加える時点で、実行時の依存のグラフ(`cargo tree -e normal`)と、ライセンス表記で増える分を確かめる |
| D-4 | 設定画面の見た目の参考にする別のリポジトリ(計画0001のD-24)は、メンテナーが、見た目の案を作る前(作業7の前)に示す |
| D-5 | 見た目の案(N-02)は、まずHTMLとSVGの静的な案で示し、メンテナーが確かめて合意してから、eframeで作る。案は、eguiの部品で作れる配置に限る。エージェントはWindowsで画面を確かめられないため、実機での確認の回数を減らす。最初からeframeで作る案は、直すたびに実機での確認が要るため採らない |
| D-6 | 2026-11-03に決定(メンテナーの判断)。メンテナーが、細部の不具合が残ってもよいので、立体的な電子レンジの絵と設定画面を早く見たいと望んだ。そのため、順序を次のように変える。(1) 本番の絵(計画0001ではPhase 3)を前倒しし、電子レンジの絵とドアの羽ばたきを、試作版`v0.2.0-alpha.1`に入れる。(2) 用語の点検(作業1、Issue #28)、モニタの変更への対応(作業10、F-07)、Aboutの依存のライセンス表記の本文は、試作版のあとに回す。(3) あとで決めること(E-1〜E-6)は、いちばん簡単な案を試作版の仮の扱いとして先に使い、v0.2.0のリリースの前に正式に決める。仮の扱いは、E-1: 環境変数`FLYING_MICROWAVE_CONFIG_DIR`(絶対パスのときだけ)で設定ファイルのフォルダを上書きする。E-2: `THIRD-PARTY-LICENSES.txt`のファイル名だけを示す。E-3: 知っている項目を`schema_version = 1`で書き、未知のキーとコメントは消える。新しい`schema_version`のファイルは、上書きの前に確認の文を示す。E-4: 設定画面を開けないときは、メッセージボックスで、開けなかったことと設定ファイルのパスを示す。E-5: フォントは`segoeui.ttf`、なければ`arial.ttf`を読み、スクリーンリーダー・URLを開くこと・クリップボードは無効のまま。E-6: 場所を取得できないときは、読み込みでは既定値、保存では画面の中にエラーを示す。v0.2.0の完了条件は変えない。試作版のリリースノートには、残る不具合と、見送ったことを書く |
| D-7 | 2026-11-03に決定(メンテナーの承認)。電子レンジの絵を描くため、`resvg` `=0.49.0`(Apache-2.0 OR MIT。2026-10-24に公開)を、既定の機能を切って(文字の描画と画像の読み込みを使わない)加える(ADR-0008の決定のとおり。導入の時期はD-6で前倒しした)。26個のcrateが一緒に入る(tiny-skia、usvg、pngなど)。`tiny-skia`と`tiny-skia-path`のライセンスがBSD-3-Clause(OSIの承認したライセンス。著作権の表示を同梱する)のため、`about.toml`の受け入れるライセンスに加える。`crc32fast`は、公開から7日たっていない1.5.4を避け、1.5.3に固定する(2026-11-03にcrates.ioと`check_publish_age.py`で確かめた) |
| D-8 | 2026-11-03に決定。見た目の案(D-5)は、`docs/design/mockups/`に置く(作業7の「案のファイルを置く場所」。この決定を入れたPRでメンテナーに確かめる)。メンテナーは、電子レンジの絵と設定画面の案を確かめ、そのまま進めることに合意した |
| D-9 | 2026-11-03に決定(メンテナーの判断)。`/s`では、設定を別のスレッドで読み始め、すべてのモニタを黒いウィンドウで覆ったあとで、最大0.5秒だけ結果を待つ。間に合わないか失敗したときは、その回は既定値で動く。アーキテクチャの`/s`の流れの図(設定を読んでから黒いウィンドウを作る順序)を、これに合わせて直した。読み込みが遅い環境(E-6のネットワーク上のRoaming AppDataなど)でも、黒で覆うまでの時間(計画0001のN-01)を守るため。`/p`は画面を覆わないので、起動時に読んでから始める |
| D-10 | 2026-11-03に記録。試作版の実装で、次のとおりにした(E-1〜E-6の仮の扱いの細部)。`schema_version`がない・整数でない・0以下のときは1として読む(E-3)。設定画面を開けないときの終了コードは7(E-4)。フォントのフォルダは`SHGetKnownFolderPath(FOLDERID_Fonts)`で求める(E-5)。スモークテストのF-03は、タイトル`Flying Microwave Settings`のウィンドウを探し(上限60秒。GPUのないランナーではWARPで描くため)、`WM_CLOSE`で閉じて、終了コード0で終わること(上限10秒)を確かめる。代わりにメッセージボックスが出たら失敗にする(作業8で決めることとした判定の方法)。壊れた設定ファイルでも`/s`が起動して入力で終わることを確かめるケースを加えた。`/c:<HWND>`でテスト用のオーナーが無効になり、閉じると有効に戻ることの自動の確認は、まだない(作業8の残り)。レビューの指摘を受けて、設定ファイルを読めなかったとき(TOMLでない、大きすぎる、読み込みの失敗)も、新しい`schema_version`のときと同じく、最初のOKで警告を示し、2回目のOKで保存するようにした(もとのファイルを黙って既定値で置き換えないため)。環境変数`FLYING_MICROWAVE_CONFIG_DIR`は、Windowsではドライブ文字で始まるパスだけを受け付ける(UNCのパスやデバイスのパスは無視する。SEC-5。E-1を正式に決めるときの観点にする)。再レビューの指摘を受けて、確かめるボタンの表示をReplaceにし、警告を出してから0.7秒(Windowsの既定のダブルクリックの時間より長い)は確認として数えないようにした(OKのダブルクリックで、警告を読まずに保存しないため)。また、環境変数に受け付けない値(空でない、相対パスやUNCのパスなど)を指定したときは、本当の設定ファイルに戻らずエラーにする(テストやローカルでの実行が、利用者のファイルを使わないため)。`\\?\C:\`の形のパスは受け付ける。PRのCIのあとで、スモークテストのF-01とF-02に、絵が描かれていること(ログに`sprite atlas:`の行があり、背景だけへの切り替えとwgpuのエラーがないこと)の確認を加えた。描画の準備に失敗しても製品は背景だけで動き続けるため、ほかの確認では見分けられないため |

## 作業

1. 用語の点検(Issue #28)。Phase 2の最初に行う(計画0001のD-24)。文書だけの変更で、軽いレビューを1回行う。
2. 設定ファイルの場所のADR(D-1、E-1、E-3、E-6)。あわせて、保存場所を「まだ決まっていない」または`directories`を使うとしている文書(設定項目仕様の設定ファイルの節、アーキテクチャの設定の保存の節、技術選定の調査の`directories`の行)を直す。
3. v0.2.0の6項目の見直し(設定項目仕様は「項目は導入フェーズの着手時に見直す」としている)。
4. `core::config`: 6項目のモデル、既定値、検証規則(TDD)。
5. `storage`: 場所の解決、サイズの上限(64KiB)、壊れたファイルの扱い、一時ファイルを使った置き換え(TDD。Windowsに依存しない部分はLinuxでもテストする。テストは利用者の設定ファイルに触れない。E-1)。
6. `/s`と`/p`への反映(F-06)。設定を読む時機は、全画面を黒で覆う時間を遅らせない形にし、読み込みにかかった時間をログに書く。アーキテクチャの`/s`の流れの図は、設定を読んでから黒いウィンドウを作る順序である。順序を変える場合は、実装の前にメンテナーに確認し、決定として記録して、図を直す。スモークテスト(計画0003)に、設定ファイルがない場合と壊れている場合を加える。
7. 見た目の案(D-5)と、メンテナーの確認。案のファイルを置く場所は、検討の経緯として残せるリポジトリの中の場所を、この作業のPRでメンテナーに確かめる。参考のリポジトリ(D-4)は、この作業の前に、読み取りだけの権限でセッションに加え、画面の構成と配置だけを参考にする。
8. 設定画面(eframe): タブ、ボタン、オーナーに対するモーダル化と前面への復帰(F-03)、保存の失敗の表示、`schema_version`の確認(F-08)、SEC-1・SEC-2(F-09)。E-2・E-4・E-5を、この作業の前に決める。スモークテストのF-03(いまはメッセージボックスのウィンドウクラス`#32770`を探す)を、設定画面に合わせて変える。判定の方法(ウィンドウの見つけ方、閉じ方、WARPでの待ち時間の上限)と、`/c:<HWND>`でテスト用のオーナーが無効になり、閉じると有効に戻ることを自動で確かめるかを、作業の前に決める。
9. 実機での確認のためのプレリリース(`v0.2.0-alpha.N`。計画0001の7.3)。作業8のあと、モーダル化と、拡大率100%・150%での見た目を確かめる。直したら、次のプレリリースで確かめ直す。その前に、計画0001の8.2(手動テスト)に、v0.2.0の機能の項目を、成功の見え方とともに加える。少なくとも、設定の保存と反映(OK・Cancel・Defaults)、`display.monitors = "primary"`、`/c`(HWNDなし。右クリックの「構成」)と`/c:<HWND>`のオーナー、新しい`schema_version`の確認(F-08)、実行中のモニタの変更(F-07)、設定画面のプロセスのDLLの差し替え(F-09。8.2の項目12の手順を`/c`でも行う)を含める。
