# 0003: v0.1.1 スモークテストと実機での確認

- ステータス: 合意済み(2026-11-02)
- 日付: 2026-11-02
- 関連: [計画0001](0001-initial-implementation-plan.md)のPhase 1の作業14、8.1、D-24、D-30、D-31、[懸念事項の確認](../reviews/0003-roadmap-concerns-to-v1.md)のK-07

## 目的

v0.1.1は、v0.1.0で先送りした確認を済ませる版である(D-30)。製品の機能は増やさない。

1. スモークテスト(作業14)を作り、CIとリリースのワークフローで、起動と終了を自動で確かめる。
2. メンテナーが、v0.1.1の候補の成果物で実機での確認を行う(D-30の完了条件)。
3. 商標の確認を済ませる(メンテナー)。
4. リリースのワークフローの所要時間を、v0.1.1のタグの実行で記録する(D-31)。

## 要件

| ID | 要件 |
| --- | --- |
| F-01 | `/s`で起動し、すべてのウィンドウの最初のフレームが表示されたあと、キー入力を送ると終了する。入力から終了までの時間を記録し、0.2秒(N-02)を超えたら失敗にする |
| F-02 | テスト用の親ウィンドウを作って`/p <HWND>`で起動し、最初のフレームが表示されたあと、親ウィンドウを破棄すると、2秒以内に終了する |
| F-03 | 認識できない引数(`/x`)で起動すると、全画面のウィンドウを作らず、設定のメッセージボックスを表示する。メッセージボックスを閉じると終了する |
| F-04 | どのテストのあとにも、テスト対象のプロセスが残っていない |
| F-05 | 起動から最初のフレームまでの時間(N-01の目安)と、使われたアダプタの名前を、ログから読んでテストの出力に記録する。N-01は実機で判定するため、ここでは失敗の条件にしない |
| N-01 | 新しい依存を加えない(`windows-sys`は既存の版を使う) |
| N-02 | テストは1回あたり2分以内に終わる。どの待ち時間にも上限を設け、止まったまま残らない |

## 設計(案)

- テストの道具: ワークスペースに、Windows専用の小さなcrate(`crates/smoke`、`publish = false`)を加える。ビルドした`.scr`のパスを引数に受け取り、F-01〜F-05を順に実行する。
  - 最初のフレームの検出は、製品のログ(`%TEMP%\flying-microwave.log`)の`first frame presented`の行で行う。v0.x系の間はログをいつも書く(D-25)。v1.0.0でログを既定で書かなくする(Phase 6)ときに、テストでだけログを有効にする方法を決める(Phase 6の作業に登録する)。
  - 入力は`SendInput`で送る。プロセスの終了は`WaitForSingleObject`で待つ。
  - 描画は、ランナーで使えるアダプタ(GPUがなければWARP)で行う。製品のコードは変えない。
- 実行する場所:
  - CIのWindowsのジョブ(x64、PRごと)。製品のビルドのあとに実行する。
  - リリースのワークフローのビルドのジョブ(x64とarm64)。arm64は、これが初めての起動の自動の確認になる(ADR-0016)。リリースノートの「arm64版について」の節(`scripts/prepare_release.py`)も合わせて直す。
- 未確認の前提: GitHubがホストするWindowsのランナーで、`SendInput`が全画面のウィンドウに届くかは確かめていない(スパイクの自己テストは、ウィンドウとサーフェスを作れることだけを確かめた)。最初のPRのCIで確かめ、届かない場合は代わりの方法(ウィンドウへのメッセージの送信など)を、メンテナーに確認してから採る。

## 作業

1. スモークテストのcrateとテスト(TDD。ログの読み取りなど、Windowsに依存しない部分は単体テストにする)。
2. CIのWindowsのジョブへの組み込み(ワークフローの変更。要承認)。
3. リリースのワークフローへの組み込み(x64とarm64。要承認)と、`prepare_release.py`のarm64の節。
4. v0.1.1の準備: 版を上げ、CHANGELOGを書き、候補の成果物でメンテナーに実機での確認を依頼する(確認の項目はD-30の完了条件のとおり)。結果を計画・スパイクの結果・説明書に反映する。
5. タグとリリース(タグはメンテナーが付ける)。所要時間を記録する。

## 決定

| ID | 内容 |
| --- | --- |
| D-1 | テストの道具は、ワークスペースのRustのcrate(`crates/smoke`)で書く(メンテナーの判断)。PowerShellのスクリプトより、ログの読み取りなどを単体テストにしやすく、製品と同じ依存で書けるため |
| D-2 | PRごとのCIのWindowsのジョブ(x64)と、リリースのワークフローのビルドのジョブ(x64とarm64)の両方で実行する(メンテナーの判断)。ワークフローへの組み込みは、計画の合意をもって承認とした |
| D-3 | F-01の終了の速さは、N-02の0.2秒で判定する(メンテナーの判断)。ランナーで不安定なら見直す |
