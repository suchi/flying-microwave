# 0006: 利用者向けのランディングページ(GitHub Pages)

- ステータス: 合意済み(2026-11-27。D-1〜D-4は推奨の案で、D-5はメンテナーの指示で決めた)
- 日付: 2026-11-27
- 関連: [計画0005](0005-v0.3.0-visuals-and-clock.md)のD-46(リポジトリの公開)、[ビジュアルデザイン方針](../design/visual-design.md)、[設定項目仕様](../design/settings.md)、[文書で使う画像](../assets/README.md)、[先行作品と知的財産上の配慮](../research/prior-art-and-ip.md)、[利用者向けREADME](../../packaging/windows/README.md)

## 目的

スクリーンセーバーの利用者が、何ができるかを知り、最新のリリースを入手できるページを、GitHub Pagesで公開する。ページは利用者だけに向け、開発者への導線は、GitHubのアイコン(リポジトリへのリンク)の1つだけにする(メンテナーの指示)。

着手の条件: リポジトリを公開していること(2026-11-27までに、メンテナーが公開した)。

## 範囲

- 対象:
  - 1枚のランディングページ(日本語と英語)と、その素材。
  - ページを公開するワークフロー。
  - 利用者が読む文書の規則(AGENTS.mdの「ドキュメント」)に、このページを加えること。
- 対象外:
  - 実機のスクリーンショット(D-4。あとで差し替える)。
  - 独自のドメイン。既定のURL(`https://suchi.github.io/flying-microwave/`)を使う。
  - 開発者向けの文書の公開(`docs/`は公開しない)。

## 要件

| ID | 要件 |
| --- | --- |
| F-01 | ページに、概要、動いている様子(D-3のアニメーション)、主な機能、動作環境、入手とインストールの要点、ライセンスと免責、プライバシー(ネットワークを使わないこと)を載せる。D-5のとおり、絵を主にし、文は短くして目立たせない(機能は短い語の並び、インストールの要点とライセンス、免責、プライバシーは、ページの下の小さな文字にする)。内容は、入手のボタンが指す版(`/releases/latest`はプレリリースを除いた最新のリリースを指す。2026-11-27には`v0.2.0`)の利用者向けREADMEとリリースノートに合わせ、その版にない機能は載せない。`v0.2.0`には飛ぶ食べ物と時計がないため、アニメーションは電子レンジだけにし、食べ物と時計は、それらを含む版を正式に公開したときに加える |
| F-02 | 入手のボタンは、GitHubのReleasesの最新のリリースのページ(`/releases/latest`)へリンクする。ファイルを直接は指さない(版ごとにファイル名が変わるため) |
| F-03 | 開発者への導線は、GitHubのアイコン(リポジトリへのリンク)だけにする。開発の文書、AGENTS.md、計画などへのリンクは置かない |
| F-04 | 日本語と英語のページを置き、互いに切り替えるリンクを置く(D-2) |
| F-05 | 見出しの背景を、素材の電子レンジが少数、ゆっくり飛ぶ(D-3)。CSSだけで動かし、`prefers-reduced-motion: reduce`のときは止める |
| N-01 | 隠し要素の存在、内容、発動条件を、ページにも、ページのソースにも書かない(AGENTS.mdの「ドキュメント」) |
| N-02 | 外部のフォント、解析のスクリプト、CDNなど、ほかのサイトから読み込むものを使わない。JavaScriptも使わない |
| N-03 | 素材は、本プロジェクトで作ったもの(`assets/sprites`、`docs/assets/banner.svg`)だけを使い、`docs/assets/README.md`の表と同じく、作者、ライセンス、出典を記録する(方針IP-3)。例外は、F-03のGitHubのアイコン(GitHub Inc.のロゴ。GitHubのロゴの使い方の決まりに従う。D-6)だけとする。先行作品を思わせる表現(トースター、翼など)を使わない(IP-2)。着想元への言及は、READMEと設定画面のAboutに限る方針(IP-1)のとおり、ページには書かない |
| N-04 | 明滅しない(ガイドラインG-3と同じく、1秒間に3回を超える明暗の変化を起こさない)。画面の幅の狭い端末でも読める |
| N-05 | ページを公開するワークフローは、公開に要る権限だけを持ち(`pages: write`と`id-token: write`はそのジョブだけ)、アクションは公式のものを完全なコミットのSHAで固定する(計画0001のR-08) |

## 決定

D-1〜D-4は、2026-11-27に、メンテナーが推奨の案で決めた(メンテナーの判断)。D-5は、同じ日に、計画の合意とあわせてメンテナーが指示した。

| ID | 決定 |
| --- | --- |
| D-1 | 公開の方式: GitHub Actionsで、`main`の`site/`を公開する。PRでレビューしたものだけが公開される。`main`の`/docs`からの公開は、`docs/`が開発者向けの文書で隠し要素を含むため、採らない。gh-pagesのブランチは、エージェントが作業ブランチにしかプッシュできず、更新のたびにメンテナーの手間がかかるため、採らない |
| D-2 | 言語: 日本語と英語(利用者向けREADMEと同じ) |
| D-3 | 動き: 軽いアニメーション(CSSだけ、少数、動きを減らす設定では止める) |
| D-4 | 画面の画像: まず素材のSVGで作り、実機のスクリーンショットは、撮り方を添えてあとでメンテナーに依頼して差し替える |
| D-5 | 見た目の方針: できるだけシンプルにし、文章は少なく、目立たないようにする。ビジュアルを主にする |
| D-6 | GitHubのアイコン(E-2を決めた): GitHub公式のInvertocat(Octiconsの`mark-github`と同じ形)を、形を変えずに使う。色は、明るい背景では黒、暗い背景では白とし、CSSの`currentColor`などで任意の色に変えない。このページの背景は暗いので、白にする。根拠は、2026-11-27にメンテナーが確かめたGitHubのブランドガイドライン(`brand.github.com/foundations/logo`)で、灰色は限られた場合だけ認められ、任意の色への変更は禁止されている。GitHubのプロフィールやプロジェクトへのリンクとしてロゴを使うことは、ガイドラインで認められている |
| D-7 | 高さの低い画面(高さ720px以下で、幅601px以上。低いウィンドウや、スマートフォンの横向き)で動きを減らす設定のときは、止まった電子レンジを小さくして(幅の8%、48〜104px)左右の端に置く(2026-11-27にメンテナーが推奨の案で決めた。再レビューの指摘L-1)。左右の位置はページの幅の割合で決め、スクロールバーが場所を取る環境でもずれないようにする。ほかの画面の止める位置は、この決定では変えない。幅960〜1200px前後、高さ721〜800px前後では、右上の1機が言語の切り替えのリンクの下地の角に少し入る(リンクが手前にあり、文字は隠れない。既知の見え方。D-7の変更のレビューの指摘L-1) |

## 実装の方式(エージェントの案)

- 構成: `site/index.html`(日本語)、`site/en/index.html`(英語)、`site/style.css`、`site/img/`(素材の写し)。ビルドの道具は使わない(依存を増やさない)。
- 素材: `assets/sprites`のSVGから、ページで使う絵をスクリプトで作るか、そのまま写す。どちらにするかは、作業1で絵の大きさを見て決め、作るときは`scripts/`に置いてテストを書く。
- ワークフロー: `.github/workflows/pages.yml`。`main`への`site/`の変更のプッシュと手動実行で動き、`actions/configure-pages`、`actions/upload-pages-artifact`、`actions/deploy-pages`を使う。版は、公開から7日以上たったものを選ぶ。
- 検査: `scripts/`に、`site/`の検査を加える。外部から読み込む指定(`http`で始まる`src`、`@import`など)がないこと、両方の言語のページがあること、リンク先のファイルがあること。隠し要素の検査は、語の一覧を持つと一覧そのものが隠し要素の記録になるため、レビューで確かめる。

## 作業

1. 計画の合意を得る。あわせて、AGENTS.mdの「利用者が読む文書」にページを加える承認を得る(2026-11-27に、どちらも得た)。
2. ページと素材と検査を作る(TDD。検査を先に書く)。ローカルでブラウザーに表示して、幅の広い画面と狭い画面のスクリーンショットで確かめる。
3. ワークフローを加える。AGENTS.mdと、`docs/README.md`、`docs/assets/README.md`、onboardingを直す。
4. 本格的なレビュー(ワークフローと規則のファイルを含むため)を受け、PRを作る。
5. マージの前に、メンテナーが次の設定を行う(2026-11-27に、メンテナーが行ったと報告した)。
   - Settings → Pages の Source を「GitHub Actions」にする。
   - Settings → Actions → General の許可するアクションに、`actions/configure-pages`、`actions/upload-pages-artifact`、`actions/deploy-pages`を加える。
   - 公開の手順の一覧の「空であること」の確認(Environments)は、Pagesが作る`github-pages`の環境を除いて読む。
6. マージのあと、ワークフローの成功と、公開されたページの表示を確かめる。2026-11-27にPR #108でマージし、Pagesのワークフローの実行(45954516816)が成功した。同じ日に、`https://suchi.github.io/flying-microwave/`の日本語と英語のページ、絵、CSSが応答200で届き、ブラウザーで開いてほかのサイトへの要求が0件であることと、見た目を確かめた(エージェントの環境から`suchi.github.io`へ接続するため、メンテナーが環境の許可するホストに加えた)。
7. 実機のスクリーンショットの撮り方をメンテナーに依頼し、受け取ったら差し替える(D-4)。

## あとで決めること

- E-1: 実機のスクリーンショットの枚数、大きさ、載せる場所(作業7で決める)。
- E-2: GitHubのアイコンの色と使い方が、GitHubのロゴの使い方の決まり(`github.com/logos`)に合うか。エージェントの環境からは、決まりのページ(`github.com/logos`、`brand.github.com`)に接続できなかった。2026-11-27に、メンテナーがガイドラインを確かめて決めた。決めた内容は次のとおりで、記録の場所はD-6。
  - 色: 暗い背景では白、明るい背景では黒。任意の色(灰色を含む)にしない。
  - 使い方: プロジェクトへのリンクとして使ってよい。形は公式のInvertocatのまま。
