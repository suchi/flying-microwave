# 0009: v0.4.0 単独アプリと、複数の画面を1つの空間にする機能

- ステータス: 案(2026-11-28)
- 日付: 2026-11-28
- 関連: [計画0008](0008-agents-md-reorganization.md)のD-3とD-4、[ADR-0012](../adr/0012-standalone-app-mode.md)、[ADR-0004](../adr/0004-store-settings-as-toml.md)、[ADR-0027](../adr/0027-settings-file-handling-from-v0.3.0.md)、[設定項目仕様](../design/settings.md)、[アーキテクチャ](../design/architecture.md)

## 目的

スクリーンセーバーとしての起動のほかに、単独のWindowsプログラムとして、ウインドウか全画面で電子レンジが飛ぶ様子を見られるようにする。複数の画面では、いまは画面ごとに別の空間があるが、すべての画面を1つの空間として飛べるようにし、それを既定にする。

## 決まっていること(計画0008の決定)

- D-3: 単独アプリはv0.4.0で出す。zipに同じ中身の`FlyingMicrowave.exe`も入れる。全画面のあいだは、ディスプレイのスリープとスクリーンセーバーの起動を止め、カーソルを隠す(マウスを動かすと数秒だけ出す)。ウインドウ表示ではどちらもしない。ウインドウは毎回1280×720(画面より大きいときは画面に収める)で画面の真ん中に開き、大きさは保存しない。
- D-4: 複数の画面を1つの空間にするオプションを加え、既定でオンにする。すべての画面を囲む四角を1つの空間にし、電子レンジは画面をまたいで飛ぶ。画面のないところを通るあいだは見えない。
- ADR-0012: `--window`、`--fullscreen`、`.exe`を引数なしで起動したときにウインドウで動く。入力では終わらず、ウインドウを閉じると終わる。F11で全画面を切り替え、Escで全画面をやめる。全画面は今の画面だけを覆う。ウインドウ表示ではカーソルを表示する。多重起動は制限しない。

## 要件

| ID | 要件 |
| --- | --- |
| F-01 | `--window`と、`.exe`の引数なしの起動で、1280×720(作業領域より大きいときは収まる大きさ)のウインドウを、主の画面の作業領域の真ん中に開く。大きさは変えられ、変えると描画もそれに合わせる |
| F-02 | `--fullscreen`で、主の画面を覆う全画面で起動する |
| F-03 | F11でウインドウ表示と全画面を切り替える。Escは全画面のときだけ、ウインドウ表示に戻す。全画面にするのは、ウインドウのある画面 |
| F-04 | 全画面のあいだは、ディスプレイのスリープとスクリーンセーバーの起動を止め、ウインドウ表示に戻すか終わると元に戻す。カーソルを隠し、マウスを動かしたら3秒だけ出す |
| F-05 | キーやマウスの入力では終わらない。ウインドウを閉じる(Alt+F4を含む)と終わる |
| F-06 | 単独アプリは、設定ファイルの設定(数、速さ、大きさ、飛び方、食べ物、時計、フレームの上限)で動く。設定ファイルには書かない |
| F-07 | GPUの準備ができないときや15秒で終わらないときは、メッセージを表示して終わる(スクリーンセーバーの全画面のように黒い画面で待たない) |
| F-08 | zipに`FlyingMicrowave.exe`を加える。中身は`FlyingMicrowave.scr`と同じ。利用者向けREADMEとランディングページに起動のしかたを書く |
| F-09 | スクリーンセーバー(`/s`)で、複数の画面を1つの空間にできる(E-2)。既定でオン。電子レンジと食べ物は、すべての画面を囲む四角の空間を飛び、画面の境をまたぐと、隣の画面に続いて見える |
| F-10 | 1つの空間のとき、画面ごとの拡大率が違っても、画面の境で位置がつながる(物理的なピクセルで空間を決める。境で大きさが少し違って見えることは受け入れる) |
| N-01 | 1つの空間でも、いまの画面ごとの空間と比べて、CPUとGPUの負荷が大きく増えない(シミュレーションは1つになり、描画は画面ごと) |
| N-02 | プレビューの枠(`/p`)と設定画面(`/c`)の動きは変えない |

## 実装の方式(エージェントの案)

- 1つの空間: すべての画面で1つの`World`を共有し、カメラを1つにする。画面ごとに、空間のうちその画面に当たる部分だけを描く投影(中心のずれた視錐台)を作る。画面を囲む四角の縦横比で`World`を作る。
- 単独アプリ: winitのウインドウを1つ作り、`World`を1つ持つ。全画面はwinitの`set_fullscreen`(ボーダーレス)で切り替える([ADR-0019](../adr/0019-screensaver-windows-without-winit-fullscreen.md)のとおり、スクリーンセーバーの窓の作り方とは分ける)。スリープを止めるのは、Windowsの`SetThreadExecutionState`(`ES_CONTINUOUS | ES_DISPLAY_REQUIRED`)。
- 表示の方針(アーキテクチャのA-8)を、このときに整理する(計画0001のD-27で、単独アプリに着手するときに整理すると決めている)。
- テストは、空間の分け方(画面の配置から投影を作る計算)、引数の判定、全画面の切り替えの状態を、`core`の単体テストで先に書く。

## あとで決めること(計画の合意のときに決める)

- E-1: 1つの空間のときの電子レンジの数。設定の数(既定14)を、(a) 空間全体の数にするか、(b) 画面の数を掛けるか、(c) 空間の広さ(画面の合計の面積)に比べて増やすか。見た目と負荷に関わる。
- E-2: 設定の形。(a) `display.monitors`に「1つの空間」(`"span"`)の値を加えて既定にする(今の`"all"`は画面ごとの空間)、(b) 別の項目(`display.one_space = true`)を加える。どちらも設定ファイルの形式に関わる。今の利用者の設定ファイルには`monitors = "all"`が書かれているため、(a)では既定を変えても、設定を保存したことのある利用者は今のままになる。`schema_version`を上げるかもあわせて決める([ADR-0027](../adr/0027-settings-file-handling-from-v0.3.0.md))。
- E-3: 単独アプリで設定画面を開く方法を用意するか(キー、メニューなど)。用意しないときは、`--settings`か`.scr`の右クリックの「構成」で開く。
