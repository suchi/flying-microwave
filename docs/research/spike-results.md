## 実機での観察

### 1回目(2026-11-01)

メンテナーがWindows 11の実機で確かめた結果。環境の情報とログは、まだ記録していない。

- 設定画面(S2): `settings-spike`の設定画面は表示された。見た目は簡素だった。
- プレビュー枠(S1): 一瞬見えたが、真っ黒だった。
- 「プレビュー」ボタン(`/s`): ボタンを押すと一瞬ウィンドウが現れ、すぐに消えた。
- S3〜S6: 確かめていない。

見た目だけでは判断できない理由:

- saver-spikeが描く色は、RGBの各成分が0.05〜0.10(8ビットで約13〜25)の暗い色で、12秒の周期でゆっくり変わる(`spikes/saver-spike/src/policy.rs`の`dark_color`。ガイドラインG-3の閃光を避けるため)。そのため、正しく描画できていても、ほぼ黒に見える。描画できたかは、ログの`frame N presented`の行で確かめる。
- `/s`がすぐに終わった理由は、ログの`EXIT requested: <理由>`の行と、その直前の`decision: ... ends the screensaver`の行で分かる。考えられる理由は、カーソルの移動(初期化から500ミリ秒の猶予のあと、16ピクセル以上)、キーやマウスボタンの押下、ウィンドウを閉じる要求、GPUの初期化の失敗やタイムアウト(`GPU init watchdog fired`)である。

次に確かめること:

1. ログ(`%TEMP%\flying-microwave-spike.log`)の内容。パスに含まれるユーザー名は伏せる。
2. 環境(上の「環境」の表の項目)。
3. 「プレビュー」ボタンを押したあと、マウスに触れずに待った場合にも、すぐに消えるか。

## CIでの観察

GitHubのWindowsランナー(`windows-2025`)で、スパイクのビルド用ワークフローの自己テストのログから得た結果。実機での確認の代わりにはならないが、実機で確かめる項目の見当を付けるために記録する。

- 対象: PR #4のコミット`d472a09`のワークフローの実行(2026-10-31)
- 環境: Windows Server 2025(ドライバのバージョン`10.0.26100.33648`からビルド26100と推測)。表示言語は英語。GPUの有無は確かめていない
- `SetDefaultDllDirectories(LOAD_LIBRARY_SEARCH_SYSTEM32)`は成功した。
- 自己テストはソフトウェアのアダプタ(WARP)を明示して要求する(`force_fallback: true`)。得られたアダプタは「Microsoft Basic Render Driver」(種類Cpu、DX12)。サーフェスの形式は`Bgra8Unorm`、表示モードは`Fifo`で設定できた。WARPを明示して要求したため、GPUが使えない環境で自動的にWARPへ切り替わるか(S6)の確認にはならない。
- `HKEY_CLASSES_ROOT\scrfile\shell`の値(ランナーの表示言語は英語。日本語の表示名は観測していないため、実機で確かめる):

| 動詞 | 既定値(表示名) | `MUIVerb` | コマンド |
| --- | --- | --- | --- |
| `open` | `T&est` | なし | `"%1" /S` |
| `config` | `C&onfigure` | `@shell32.dll,-10209` | `"%1"` |
| `install` | `&Install` | `@shell32.dll,-10210` | `rundll32.exe desk.cpl,InstallScreenSaver %l` |
